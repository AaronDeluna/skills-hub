# Ревью управления зависимостями

Скилл запускает `orchestrator`. Файлы проекта ты только читаешь. Проверки по файлам сборки и
дерево зависимостей делает скрипт `deps.py`; ты подтверждаешь спорные строки по
`references/rules.md` и записываешь результат командой скрипта. Отчёт собирает скрипт.
Состояние - в `openspec/changes/<имя>/outputs/FINDINGS.md` (`deps_status` в шапке), поэтому
оборванный чат продолжается с того же места.

## Когда использовать / когда не использовать

| `deps_status` в `openspec/changes/<имя>/outputs/FINDINGS.md` | Что делаешь |
|---------------------------------------------------------|-------------|
| файла нет или `reported` | шаги 1-6 |
| `scanned` | шаги 2-6 |
| `tree-done` | шаги 3-6 |

Не этот скилл: обновить фрейм - `env-update`; доставить зависимости фрейма - `env-check`,
режим setup; поправить файлы сборки - человек по отчёту.

## Предусловия

- Файлы работы - в каталоге изменения OpenSpec `openspec/changes/<имя>/` (`<имя>` - строка
  `ИЗМЕНЕНИЕ:` из `os_work.py next` оркестратора): артефакты `proposal.md`, `design.md`,
  `tasks.md` и рабочие файлы `outputs/`. Общее для проекта (конспект документации, `ENV.json`) -
  `openspec/pvatf/`. Пути в командах скриптов определяются сами - подставлять их не нужно.
- Запуск из корня проекта; в корне `pom.xml`, `build.gradle(.kts)` или `settings.gradle(.kts)`.
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).
- Для шага 2 - Maven (`./mvnw` или `mvn`) или Gradle (`./gradlew` или `gradle`). Нет - шаг 2 с `--no-build`.
- Агент `pvatf-docs` в `.gigacode/agents/` (из папки `agents/` набора) - только для строки D-P2.

**Скрипт - `.gigacode/skills/dependency-review/scripts/deps.py`.** Нет по этому пути -> найди
один раз: `find . ~/.gigacode -path "*dependency-review/scripts/deps.py" 2>/dev/null | head -1`.

## Шаги

1. Проверки по файлам сборки:
   ```
   python3 .gigacode/skills/dependency-review/scripts/deps.py scan
   ```
   Код 1 и `НЕТ СБОРКИ` -> скажи человеку вывод дословно, дальше не идёшь.
2. Дерево зависимостей (таймаут команды 600 секунд; сборщик скрипт ограничивает 540 секундами на всю команду):
   ```
   python3 .gigacode/skills/dependency-review/scripts/deps.py tree
   ```
   Сборщик скачивает артефакты из репозитория. Человек запретил запускать сборку -> `tree --no-build`.
3. Следующая строка на проверку:
   ```
   python3 .gigacode/skills/dependency-review/scripts/deps.py next
   ```
   `ВСЁ ПРОВЕРЕНО` -> шаг 5.
4. Проверь строку по `references/rules.md`, раздел из «КАК ПРОВЕРИТЬ», и запиши результат:
   ```
   python3 .gigacode/skills/dependency-review/scripts/deps.py mark <N-n> <PASS | VIOLATION | N/A | NEEDS-HUMAN> --note "<что увидел>" [--where <файл:строка>] [--level <уровень>]
   ```
   Ещё одно место того же правила - `deps.py add <D-id> --where <файл:строка> --note "<что не так>"`.
   `mark` закрывает строку, которую выдал `next` (номер `N-n`); `add` добавляет новую строку
   нарушения к правилу (номер `D-n`), строку `N-n` после этого всё равно закрывай `mark`.
   Пример: `next` выдал `N-13 D-20`, нарушение в двух модулях ->
   `deps.py mark N-13 VIOLATION --where core-utils/pom.xml:51 --note "hamcrest в compile, нужен только тестам"`
   и `deps.py add D-20 --where api-tests/pom.xml:30 --note "testng в compile, нужен только тестам"`.
   Исходник `deps.py` не читаешь: синтаксис - только здесь.
   Строка D-P2 - вопрос агенту `pvatf-docs`, порядок - в разделе D-P2 файла правил.
   Потом снова шаг 3.
5. Вывод для отчёта - 2-3 предложения обычным языком: в каком состоянии зависимости, что
   чинить первым и почему. Опирайся только на строки `VIOLATION` и `NEEDS-HUMAN` из
   `FINDINGS.md`. Отчёт:
   ```
   python3 .gigacode/skills/dependency-review/scripts/deps.py report --summary "<вывод>"
   ```
   Код 1 и `НЕ ПРОВЕРЕНО` -> шаг 3.
6. Итог по шаблону из раздела «Контракт».

## Контракт «вход -> выход»

Вход: корень проекта; необязательно - «сборку не запускать».

Выход:
- `openspec/changes/<имя>/outputs/FINDINGS.md` - строки по правилам и статусы (пишет скрипт);
- `openspec/changes/<имя>/outputs/DEPS.json` - то же для скрипта;
- `openspec/changes/<имя>/outputs/tree.txt` - вывод сборщика;
- `openspec/changes/<имя>/outputs/DEPENDENCY-ANALYSIS.md` - отчёт (пишет скрипт).

Ответ в чате строго по шаблону, данные - из вывода `report`:
```
Зависимости: <СБОРКА> · <СТРУКТУРА> · отчёт openspec/changes/<имя>/outputs/DEPENDENCY-ANALYSIS.md
Находки: <строка НАХОДКИ>
Дерево: <строка ДЕРЕВО из шага 2>
Главное: <строка ГЛАВНОЕ>
Осталось человеку: <строки NEEDS-HUMAN из раздела «Требует внимания человека»; нет - «нет»>
Дальше: <строка ФРЕЙМ не «ok» -> «Напишите: /orchestrator обнови окружение»; иначе «правки файлов сборки - по отчёту, разделы по важности»>
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| `scan`, `next`, `mark`, `add` или `report` не закончили работу за 120 секунд | Прерви вызов, покажи вывод дословно, дальше не иди. Повторно не запускай |
| `tree` вывел `ТАЙМАУТ` или не закончил работу за 600 секунд | Повтори `tree`, не больше 2 раз: сборщик продолжит со скачанного. Снова таймаут - `tree --no-build`; в итоге «Дерево: не построено: таймаут» |
| `tree`: строка D-10 `NEEDS-HUMAN` «дерево не построено» | Не повторяй. Идёшь дальше, строка попадёт в «Осталось человеку» |
| `НЕТ ДАННЫХ` | Шаг 1 |
| `mark`: `НЕТ СТРОКИ` | Шаг 3 - номер строки бери из `СТРОКА:` |
| `pvatf-docs`: `MCP НЕДОСТУПЕН` | Строка D-P2 - по разделу D-P2 файла правил, пункт 3 |
| Человек просит поправить файлы сборки | Не в этом скилле. Скажи: «Ревью только читает проект. Правки - по отчёту; версию фрейма выравнивает /orchestrator обнови окружение» |

## Чек-лист проверки

- [ ] Файлы проекта не изменены: `git status --porcelain -- . ':!.gigacode'` - то же, что до запуска.
- [ ] Каждая строка `TODO` и `CANDIDATE` закрыта командой `mark`; сам строк в `FINDINGS.md` не правил.
- [ ] `report` вернул 0.
- [ ] Ответ в чате - по шаблону; коммит не сделан.
