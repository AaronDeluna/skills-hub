# Генерация автотеста по плану

Скилл запускает `orchestrator`. Код шагов пишет агент `pvatf-generator`, тест-класс собирает
скрипт, проверяет скрипт. Ты ведёшь цикл по шагам генерации G и добываешь документацию.
Состояние - в `design.md` (колонка «Статус» раздела 3 и `plan_status`), поэтому оборванный чат
продолжается с первого G со статусом `todo`. Сначала прочитай `references/autotest-rules.md`.

## Когда использовать / когда не использовать

| `plan_status` в `design.md` | Что делаешь |
|---------------------------|-------------|
| `planned`, `generating` | шаги 1-9 |
| `assembled` | шаги 5-9 |
| `checked`, ДЕЙСТВИЕ `autotest-gen <ключ> запуск` или `apply · запуск теста` | шаги 7-9 (запуск) |
| `checked` | только итог по шаблону |
| `draft` или файла нет | не этот скилл - `autotest-plan` |

## Предусловия

- Файлы работы - в каталоге изменения OpenSpec `openspec/changes/<имя>/` (`<имя>` - строка
  `ИЗМЕНЕНИЕ:` из `os_work.py next` оркестратора): артефакты `proposal.md`, `design.md`,
  `tasks.md` и рабочие файлы `outputs/`. Общее для проекта (конспект документации, `ENV.json`) -
  `openspec/pvatf/`. Пути в командах скриптов определяются сами - подставлять их не нужно.
- `openspec/changes/<имя>/design.md` с `plan_status` из таблицы выше.
- `openspec/pvatf/env/ENV.json` (команда компиляции) - от `env-check`.
- `openspec/changes/<имя>/outputs/ENV-TC.md` с `env_tc: ready` - окружение под ТК настроено
  (`env-check`, режим setup с ключом). Нет файла или `env_tc: missing` -> не генерируй: закончи
  строкой «Окружение под ТК не готово - /orchestrator продолжи генерацию <ключ>» (оркестратор
  сначала настроит окружение). Модули и конфигурацию сам не правишь.
- Агенты `pvatf-generator`, `pvatf-docs` в `.gigacode/agents/` (из папки `agents/` набора).
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).

**Скрипт - `.gigacode/skills/autotest-gen/scripts/at_tools.py`.** Нет по этому пути -> найди
один раз: инструментом поиска файлов: файл `at_tools.py` в каталоге проекта и в `~/.gigacode` (работает и на Windows).

## Шаги

1. Правила и конспект для генератора (запускай в начале каждого чата и после пополнения конспекта):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py rules <ключ>
   ```
2. Задание на следующий G:
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py next <ключ>
   ```
   `ВСЕ G ГОТОВЫ` -> шаг 4.
3. Один G - по `references/generation.md`: агент `pvatf-generator` с заданием из вывода
   дословно -> по его статусу `mark` / вопросы документации -> снова шаг 2. Не больше 2
   кругов документации на один G, потом `mark ... stub`.
   После `mark <ключ> <G-n> ok` - сразу компиляция этой G (таймаут команды 600 секунд):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py compile <ключ> <G-n>
   ```
   `КОМПИЛЯЦИЯ: ok` -> шаг 2. `failed` -> сделай строку `НУЖНО`: `mark <ключ> <G-n> todo`, `next`,
   задание агенту дословно (ошибки скрипт уже вписал в раздел «ИСПРАВЬ»). Не больше 2 кругов,
   потом `mark <ключ> <G-n> stub`. `НУЖНО: нет команды компиляции` -> скилл env-check, режим check,
   потом снова compile.
   - нельзя: перейти к следующей G при `КОМПИЛЯЦИЯ: failed` -> нужно: сначала исправить эту G.
4. Сборка тест-класса:
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py assemble <ключ>
   ```
5. Проверка (таймаут команды 600 секунд; компиляцию скрипт ограничивает 540 секундами):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py check <ключ>
   ```
   Строки `НУЖНО: <G-n> - находок в классах шагов` -> классы шагов сам не правишь: `mark <ключ>
   <G-n> todo`, `next`, задание агенту (находки скрипт уже вписал в раздел «ИСПРАВЬ»), `mark`,
   `compile` (шаг 3), потом `assemble` и снова check. Остальные находки - тест-класса: исправляй
   по `references/generation.md`, раздел «Исправление находок», через фрагменты, и запускай check
   снова. Не больше 3 кругов. Строки `STUB` не исправляешь - они уходят в итог.
6. `ИТОГ: находок 0` и `plan_status: checked` -> сразу шаг 7. Остались только строки `STUB`
   (`plan_status: checked`) -> шаги 7-8 не делаешь: итог (шаг 9) со строками STUB в «Осталось
   человеку», тест с заглушкой не запускается. Иначе после 3 кругов - итог со списком оставшихся
   находок, шаги 7-9 не делаешь.
7. Запуск - всегда, сразу после чистой проверки. Человека не спрашиваешь: работа не закончена,
   пока тест не запущен.
   - нельзя: после `check` спросить «Архивировать или прогнать тест?» -> нужно: запустить тест
     и показать итог запуска.
   Запусти (таймаут команды 600 секунд; запуск скрипт ограничивает 540 секундами):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py run <ключ>
   ```
   Скрипт сначала проверяет окружение под ТК. Строка `ОКРУЖЕНИЕ НЕ ГОТОВО` -> тест не
   запускался: закончи итогом с результатом `окружение не готово` и строками `НУЖНО` в
   «Осталось человеку»; оркестратор сначала настроит окружение (env-check), потом снова запуск.
   Человек сам написал «уже запускал сам» -> вместо запуска разбери отчёт его прогона: та же
   команда с `--report-only`.
8. Каждую строку `ПАДЕНИЕ <метод> <вид>: <сообщение>` разбери по виду:
   - `СТЕНД` (нет связи, нет доступа, 401/403/5xx): код не правь. В «Осталось человеку» -
     `<метод>: стенд - <сообщение дословно>`.
   - `ПРОВЕРКА` (не сошёлся ассерт): ожидаемые значения из ТК не меняй. Найди в тест-методе
     шаг с этим ассертом (комментарий `// Шаг <n>:`). В «Осталось человеку» -
     `шаг <n>: ТК ждёт <ожидаемое>, стенд вернул <фактическое> - уточнить ТК или стенд`.
     Нельзя: поменять ожидаемое `200` на `400`, чтобы тест прошёл. Нужно: оставить `200`
     и отдать расхождение человеку.
   - `КОД` (исключение в коде теста или шагов: `NullPointerException`, `ClassCastException`,
     `NoSuchElementException` и другие): исправь по `references/generation.md`, раздел
     «Исправление находок», только в файлах из строк «Файлы шагов» фрагментов и в тест-классе.
     Потом `check` (шаг 5), потом снова `run`. Не больше 2 кругов, дальше - в «Осталось человеку».
9. Итог по шаблону ниже.

## Контракт «вход -> выход»

Вход: ключ тест-кейса.

Выход:
- тест-класс по пути `test_file` из шапки плана; классы шагов, страниц, файлы данных - по
  строкам «Файлы шагов» фрагментов;
- `openspec/changes/<имя>/outputs/fragments/G-<n>.md` - фрагменты (пишет агент);
- `openspec/changes/<имя>/outputs/CHECK.md` - итог проверки (пишет скрипт);
- `design.md`: статусы G, `plan_status: checked`, после запуска `run_status` (пишет скрипт);
- `openspec/changes/<имя>/outputs/RUN.md` и `run.log` - итог и вывод запуска (пишет скрипт `run`).

Ответ в чате строго по шаблону:
```
Автотест: <ключ> · <test_file>
Шаги генерации: ok <n> · stub <n> (<G-n: причина>) · blocked <n>
Создано и изменено: <файлы через запятую>
Конспект пополнен: <D-id через запятую; нет - «нет»>
Проверка: находок <n> · компиляция <ok | failed | skipped>
Запуск: <строка ЗАПУСК из вывода; не запускался - «-»>
Результат: <passed | failed | no-tests | no-report | timeout | error | окружение не готово | не запускался (находки check)> · тестов <n> · упало <n>
Падения: <метод - СТЕНД | ПРОВЕРКА | КОД - сообщение; нет - «нет»>
Исправлено: <файл - что; нет - «нет»>
Осталось человеку: <заглушки, оставшиеся находки check, строки из шага 8; нет - «нет»>
Дальше: <passed - «Напишите: /orchestrator разметь тесты»; иначе - «После исправления: /orchestrator запусти автотест <ключ>»>
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| Скрипт скилла без компиляции и без MCP-вызова не закончил работу за 120 секунд | Прерви вызов, покажи вывод дословно, дальше не иди. Повторно не запускай |
| `next`: `plan_status draft` | Скажи, что план не утверждён, предложи `/orchestrator разбери ТК <ключ>`. Дальше не иди |
| Агент ответил не по шаблону или не записал фрагмент | Перезапусти агента 1 раз с тем же заданием. Снова - `mark <ключ> <G> stub`, причина в «Решения и блокеры» плана |
| `pvatf-docs`: `MCP НЕДОСТУПЕН` | `mark <ключ> <G> stub`; в итоге - «документация недоступна» |
| `assemble`: `ФАЙЛ ЕСТЬ` | Тест-класс с таким именем написан человеком. Шапку руками не правь: `python3 .gigacode/skills/autotest-plan/scripts/tc_plan.py rename <ключ> <Имя>GenTest` (к имени - `Gen`), потом строка `ДАЛЬШЕ` (validate и «да» человека), потом assemble снова |
| `compile`: `КОМПИЛЯЦИЯ таймаут` | Запусти compile ещё раз. Снова таймаут - `mark <ключ> <G-n> stub`, в итоге «компиляция G не проверена» |
| `check`: `КОМПИЛЯЦИЯ таймаут` | Запусти check ещё раз. Снова таймаут - `--no-compile`, в итоге «компиляция не проверена» |
| `check`: ошибка компиляции в файле, которого нет во фрагментах | Не правь. В «Осталось человеку»: проект не компилировался и без нового теста |
| `run`: `СНАЧАЛА check` | Шаги 5-6, потом снова `run` |
| `run`: `ОКРУЖЕНИЕ НЕ ГОТОВО` | Тест не запускался. Итог с результатом `окружение не готово`, строки `НУЖНО` - в «Осталось человеку». Модули и конфигурацию сам не правишь |
| `run`: `НЕЛЬЗЯ ЗАПУСТИТЬ` | Покажи строку дословно, итог запуска с результатом `не запускался` |
| `run`: `РЕЗУЛЬТАТ: timeout` | Не повторяй. В «Осталось человеку»: тест не уложился в 540 секунд, запустить вручную и написать «уже запускал сам» |
| `run`: `РЕЗУЛЬТАТ: no-report` или `error` без строк `ПАДЕНИЕ` | Сборка упала до тестов. Покажи строки под `РЕЗУЛЬТАТ` дословно; ошибка компиляции -> шаг 5, иначе - в «Осталось человеку» |

## Чек-лист проверки

- [ ] Каждый G прошёл через агента `pvatf-generator`; код шагов сам не писал.
- [ ] После каждого ответа `pvatf-docs` запущен `notes.py merge <метка> doc-notes` (код 0) и `rules` перезапущен.
- [ ] Тест-класс создан скриптом `assemble`, а не вручную.
- [ ] Последний `check` - после всех правок; его итог в ответе.
- [ ] После чистого `check` тест запущен без вопроса человеку; при `ПРОВЕРКА` ожидаемые значения ТК не менялись.
- [ ] Ответ в чате - по шаблону; коммит не сделан.
