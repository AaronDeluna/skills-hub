# Генерация автотеста по плану

Скилл запускает `orchestrator`. Код шагов пишет агент `pvatf-generator`, тест-класс собирает
скрипт, проверяет скрипт. Ты ведёшь цикл по шагам генерации G и добываешь документацию.
Состояние - в `PLAN.md` (колонка «Статус» раздела 3 и `plan_status`), поэтому оборванный чат
продолжается с первого G со статусом `todo`. Сначала прочитай `references/autotest-rules.md`.

## Когда использовать / когда не использовать

| `plan_status` в `PLAN.md` | Что делаешь |
|---------------------------|-------------|
| `planned`, `generating` | шаги 1-6 |
| `assembled` | шаги 5-6 |
| `checked` | только итог по шаблону |
| `draft` или файла нет | не этот скилл - `autotest-plan` |

## Предусловия

- `.gigacode/data/autotest/<ключ>/PLAN.md` с `plan_status` из таблицы выше.
- `.gigacode/data/autotest/ENV.json` (команда компиляции) - от `env-check`.
- Агенты `pvatf-generator`, `pvatf-docs` в `.gigacode/agents/` (ставит `orchestrator`).
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).

**Скрипт - `.gigacode/skills/autotest-gen/scripts/at_tools.py`.** Нет по этому пути -> найди
один раз: `find . ~/.gigacode -path "*autotest-gen/scripts/at_tools.py" 2>/dev/null | head -1`.

## Шаги

1. Правила и конспект для генератора (запускай в начале каждого чата и после пополнения конспекта):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py rules <ключ>
   ```
2. Задание на следующий G:
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py next <ключ>
   ```
   `ВСЕ G ГОТОВЫ` -> шаг 4.
3. Один G - по `references/generation.md`: агент `pvatf-generator` с заданием из вывода
   дословно -> по его статусу `mark` / вопросы документации -> снова шаг 2. Не больше 2
   кругов документации на один G, потом `mark ... stub`.
4. Сборка тест-класса:
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py assemble <ключ>
   ```
5. Проверка (таймаут команды 900 секунд):
   ```
   python3 .gigacode/skills/autotest-gen/scripts/at_tools.py check <ключ>
   ```
   Находки исправляй по `references/generation.md`, раздел «Исправление находок», и запускай
   check снова. Не больше 3 кругов. Строки `STUB` не исправляешь - они уходят в итог.
6. `ИТОГ: находок 0` и `plan_status: checked` -> итог по шаблону. Иначе после 3 кругов -
   итог со списком оставшихся находок.

## Контракт «вход -> выход»

Вход: ключ тест-кейса.

Выход:
- тест-класс по пути `test_file` из шапки плана; классы шагов, страниц, файлы данных - по
  строкам «Файлы шагов» фрагментов;
- `.gigacode/data/autotest/<ключ>/fragments/G-<n>.md` - фрагменты (пишет агент);
- `.gigacode/data/autotest/<ключ>/CHECK.md` - итог проверки (пишет скрипт);
- `PLAN.md`: статусы G, `plan_status: checked` (пишет скрипт).

Ответ в чате строго по шаблону:
```
Автотест: <ключ> · <test_file>
Шаги генерации: ok <n> · stub <n> (<G-n: причина>) · blocked <n>
Создано и изменено: <файлы через запятую>
Конспект пополнен: <D-id через запятую; нет - «нет»>
Проверка: находок <n> · компиляция <ok | failed | skipped>
Осталось человеку: <заглушки и находки; нет - «нет»>
Дальше: «Напишите: /orchestrator разметь тесты» (проверка разметки нового класса) и «/orchestrator проверь автотест <test_file>» (дубли и константы)
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| `next`: `plan_status draft` | Скажи, что план не утверждён, предложи `/orchestrator разбери ТК <ключ>`. Дальше не иди |
| Агент ответил не по шаблону или не записал фрагмент | Перезапусти агента 1 раз с тем же заданием. Снова - `mark <ключ> <G> stub`, причина в «Решения и блокеры» плана |
| `pvatf-docs`: `MCP НЕДОСТУПЕН` | `mark <ключ> <G> stub`; в итоге - «документация недоступна» |
| `assemble`: `ФАЙЛ ЕСТЬ` | Тест-класс с таким именем написан человеком. Поменяй `class` и `test_file` в шапке плана (добавь к имени `Gen`), запусти assemble снова |
| `check`: `КОМПИЛЯЦИЯ таймаут` | Запусти check ещё раз. Снова таймаут - `--no-compile`, в итоге «компиляция не проверена» |
| `check`: ошибка компиляции в файле, которого нет во фрагментах | Не правь. В «Осталось человеку»: проект не компилировался и без нового теста |

## Чек-лист проверки

- [ ] Каждый G прошёл через агента `pvatf-generator`; код шагов сам не писал.
- [ ] Каждый ответ `pvatf-docs` записан в конспект `.gigacode/data/doc-notes/<метка>.md` и `rules` перезапущен.
- [ ] Тест-класс создан скриптом `assemble`, а не вручную.
- [ ] Последний `check` - после всех правок; его итог в ответе.
- [ ] Ответ в чате - по шаблону; коммит не сделан.
