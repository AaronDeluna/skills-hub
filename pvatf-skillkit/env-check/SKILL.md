# Проверка и настройка окружения PVATF

Скилл запускает `orchestrator`. Сам ты код тестов не пишешь и версию фрейма не меняешь.
Режим приходит от оркестратора: `check` (только проверить) или `setup` (проверить и
доставить недостающее). Сначала прочитай `references/autotest-rules.md` - общие правила окружения и генерации.

## Когда использовать / когда не использовать

| Просьба | Режим |
|---------|-------|
| «проверь окружение», «готов ли проект», перед генерацией автотестов | `check` |
| «настрой окружение», «подключи фрейм», «почини окружение по отчёту» | `setup` |
| «обнови фрейм», «обнови окружение» | не этот скилл - `env-update` |

## Предусловия

- Запуск из корня проекта автотестов (там, где `pom.xml` / `build.gradle(.kts)` и `.gigacode/`).
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).
- Maven или Gradle (или обёртка `mvnw` / `gradlew` в корне) - для проверки E6.
- Режим `setup`: агент `pvatf-docs` (ставит `orchestrator`); документация MCP - только через него.

**Скрипты лежат в `.gigacode/skills/env-check/scripts/`.** Скрипта по этому пути нет -> найди
один раз: `find . ~/.gigacode -path "*env-check/scripts/env_check.py" 2>/dev/null | head -1` -
и подставляй найденный путь.

## Шаги

### Режим check

1. Запусти (таймаут команды - 1000 секунд; компиляцию скрипт сам ограничивает 900 секундами):
   ```
   python3 .gigacode/skills/env-check/scripts/env_check.py
   ```
   Скрипт сам выбирает команду компиляции (`mvn -q -DskipTests test-compile` или
   `gradle -q testClasses`, обёртка в приоритете), пишет `.gigacode/data/autotest/ENV.json`
   и печатает сводку.
2. Покажи человеку сводку по шаблону из раздела «Контракт» - строки `СТАТУС`, `E1`-`E6` и
   все строки `ПРОБЛЕМА` дословно.
3. `СТАТУС: failed` -> предложи одной строкой: «Напишите: `/orchestrator настрой окружение`».
   Ничего не исправляй сам.

### Режим setup

1. Выполни режим check, шаг 1. `СТАТУС: ok` -> скажи «окружение в порядке», закончи.
2. Открой `references/setup.md` и пройди его по порядку: каждая строка `ПРОБЛЕМА` - одна
   правка по таблице, имена берутся только из ответа `pvatf-docs` или проекта-примера.
3. После всех правок снова запусти env_check.py (шаг 1 режима check).
4. Новых проблем стало больше или осталась та же `critical` -> верни правки
   (`git checkout -- <файл>` по списку из `ENV-SETUP.md`), запиши причину, закончи.
   Не больше 3 кругов «правка -> проверка».

## Контракт «вход -> выход»

Вход: режим (`check` / `setup`), необязательно - путь к проекту-примеру (драфту).

Выход:
- `.gigacode/data/autotest/ENV.json` - полный результат (пишет скрипт, руками не правится);
- режим setup - `.gigacode/data/autotest/ENV-SETUP.md` по шаблону `references/setup.md`;
- ответ в чате строго по шаблону:

```
Окружение: <ok | warning | failed> (проверено <дата время из ENV.json>)
Проект: <строка ПРОЕКТ из вывода>
Версия фрейма: <строки ВЕРСИЯ через «; » или «не найдена»>
Проверки:
- E1..E6 · <название> · <статус> · <детали>
Проблемы: <по строке на ПРОБЛЕМА; нет - «нет»>
Сделано (только setup): <файл - что изменено; нет - «ничего»>
Дальше: <одна команда для человека>
```

Коды выхода env_check.py: 0 - ok или warning, 1 - failed, 2 - неверный запуск.

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| Скрипт скилла без компиляции и без MCP-вызова не закончил работу за 120 секунд | Прерви вызов, покажи вывод дословно, дальше не иди. Повторно не запускай |
| Код выхода 2 | Покажи вывод дословно, проверь, что запускаешь из корня проекта, запусти ещё раз. Снова 2 - остановись |
| `COMPILE_TIMEOUT` | Запусти ещё раз с `--timeout 1800`, таймаут команды 1900 секунд. Снова таймаут - скажи человеку проверить доступ к репозиторию зависимостей; дальше не иди |
| `BUILD_TOOL_NOT_FOUND` | Скажи, какой команды нет. Сам ничего не устанавливай |
| `pvatf-docs` вернул `MCP НЕДОСТУПЕН` или «НЕТ В ДОКЕ» | Эту проблему не исправляй, запиши в `ENV-SETUP.md` «не исправлено: нет в документации» |
| Скрипт упал с трассировкой | Покажи последние 20 строк вывода, ничего не исправляй вручную |
