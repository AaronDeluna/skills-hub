# Проверка и настройка окружения PVATF

Скилл запускает `orchestrator`. Сам ты код тестов не пишешь и версию фрейма не меняешь.
Режим приходит от оркестратора: `check` (только проверить), `setup` (проверить и
доставить недостающее) или `init` (создать каркас нового проекта, потом `setup`). Сначала прочитай `references/autotest-rules.md` - общие правила окружения и генерации.

## Когда использовать / когда не использовать

| Просьба | Режим |
|---------|-------|
| «проверь окружение», «готов ли проект», перед генерацией автотестов | `check` |
| «настрой окружение», «подключи фрейм», «почини окружение по отчёту» | `setup` |
| «создай проект автотестов», «новый проект с нуля», в каталоге нет файла сборки | `init` |
| «обнови фрейм», «обнови окружение» | не этот скилл - `env-update` |

## Предусловия

- Запуск из корня проекта автотестов (там, где `pom.xml` / `build.gradle(.kts)` и `.gigacode/`);
  режим `init` - из пустого каталога будущего проекта.
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).
- Maven или Gradle (или обёртка `mvnw` / `gradlew` в корне) - для проверки E6.
- Режим `setup`: агент `pvatf-docs` (из папки `agents/` набора); документация MCP - только через него.

**Скрипты лежат в `.gigacode/skills/env-check/scripts/`.** Скрипта по этому пути нет -> найди
один раз: `find . ~/.gigacode -path "*env-check/scripts/env_check.py" 2>/dev/null | head -1` -
и подставляй найденный путь.

## Шаги

### Режим check

1. Версии фрейма: вызови MCP-инструмент `get_pvat_release_notes` (таймаут 120 секунд; таймаут или
   ошибка -> повтори 1 раз). Ответ запиши без правок в `.gigacode/data/autotest/release-notes.md`.
   Снова ошибка -> файл не пиши, ключ `--release-notes` ниже не добавляй, в ответе строка
   «Версия фрейма»: `самая новая - не сравнивалась: <ошибка>`.
   Запусти (таймаут команды - 1000 секунд; компиляцию скрипт сам ограничивает 900 секундами):
   ```
   python3 .gigacode/skills/env-check/scripts/env_check.py --release-notes .gigacode/data/autotest/release-notes.md
   ```
   Скрипт сам выбирает команду компиляции (`mvn -q -DskipTests test-compile` или
   `gradle -q testClasses`, обёртка в приоритете), пишет `.gigacode/data/autotest/ENV.json`
   и печатает сводку.
2. Покажи человеку сводку по шаблону из раздела «Контракт» - строки `СТАТУС`, `E1`-`E6` и
   все строки `ПРОБЛЕМА` дословно.
3. `СТАТУС: failed` -> предложи одной строкой: «Напишите: `/orchestrator настрой окружение`».
   Ничего не исправляй сам.
4. Строка `ПРОБЛЕМА: info · FRAME_OUTDATED` -> фрейм отстаёт от самой новой версии. Статус она не
   меняет. В строке «Дальше» добавь: «`/orchestrator обнови окружение` - обновить фрейм до <версия>».

### Режим init

1. Значения каркаса:
   ```
   python3 .gigacode/skills/env-check/scripts/env_init.py defaults
   ```
   `ПРОЕКТ УЖЕ ЕСТЬ` -> каркас не нужен: выполни режим setup, закончи.
   groupId, artifactId и пакет названы в просьбе -> бери их. Иначе спроси одной строкой:
   «groupId, artifactId и пакет тестов через запятую? Пустой ответ - <значения из строки ПО УМОЛЧАНИЮ>».
2. Каркас (только Maven: проект-пример фрейма - Maven; Gradle просят -> скажи, что каркас
   создаётся только на Maven, и закончи):
   ```
   python3 .gigacode/skills/env-check/scripts/env_init.py create --group <groupId> --artifact <artifactId> --package <пакет>
   ```
   Скрипт пишет `pom.xml` без зависимостей фрейма, каталоги тестов и `ENV-INIT.md`. Имена
   фрейма он не пишет: их берёт режим setup из документации.
3. Выполни режим setup целиком, затем `references/setup.md`, раздел «Новый проект».


### Режим setup

1. Выполни режим check, шаг 1. `СТАТУС: ok` -> скажи «окружение в порядке», закончи.
2. Открой `references/setup.md` и пройди его по порядку: каждая строка `ПРОБЛЕМА` - одна
   правка по таблице, имена берутся только из ответа `pvatf-docs` или проекта-примера.
3. После всех правок снова запусти env_check.py (шаг 1 режима check).
4. Новых проблем стало больше или осталась та же `critical` -> верни правки
   (по списку из `ENV-SETUP.md`: изменённый файл - `git checkout -- <файл>`, созданный файл или каталог - `rm -r <путь>`, только для пути из `ENV-SETUP.md` внутри корня проекта), запиши причину, закончи.
   Проблем стало меньше, но `СТАТУС` не `ok` -> снова шаг 2 по оставшимся строкам `ПРОБЛЕМА`. Не больше 3 кругов «правка -> проверка»; после третьего круга правки не возвращай, оставшиеся проблемы запиши в `ENV-SETUP.md` строкой «не исправлено: 3 круга», закончи.

## Контракт «вход -> выход»

Вход: режим (`check` / `setup` / `init`), необязательно - путь к проекту-примеру (драфту);
для `init` - groupId, artifactId, пакет.

Выход:
- `.gigacode/data/autotest/ENV.json` - полный результат (пишет скрипт, руками не правится);
- режим setup - `.gigacode/data/autotest/ENV-SETUP.md` по шаблону `references/setup.md`;
- режим init - ещё `pom.xml`, каталоги тестов, `.gigacode/data/autotest/ENV-INIT.md`, базовый тест-класс;
- `.gigacode/data/autotest/release-notes.md` - ответ `get_pvat_release_notes` без правок;
- ответ в чате строго по шаблону:

```
Окружение: <ok | warning | failed> (проверено <дата время из ENV.json>)
Проект: <строка ПРОЕКТ из вывода>
Версия фрейма: <строки ВЕРСИЯ через «; » или «не найдена»> · самая новая <строка САМАЯ НОВАЯ или «не сравнивалась: <причина>»>
Проверки:
- E1..E6 · <название> · <статус> · <детали>
Проблемы: <по строке на ПРОБЛЕМА; нет - «нет»>
Сделано (только setup): <файл - что изменено; нет - «ничего»>
Дальше: <одна команда для человека>
```

Коды выхода env_check.py: 0 - ok или warning, 1 - failed, 2 - неверный запуск.

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| Скрипт скилла без компиляции и без MCP-вызова не закончил работу за 120 секунд | Прерви вызов, покажи вывод дословно, дальше не иди. Повторно не запускай |
| Код выхода 2 | Покажи вывод дословно, проверь, что запускаешь из корня проекта, запусти ещё раз. Снова 2 - остановись |
| `COMPILE_TIMEOUT` | Запусти ещё раз с `--timeout 1800`, таймаут команды 1900 секунд. Снова таймаут - скажи человеку проверить доступ к репозиторию зависимостей; дальше не иди |
| `BUILD_TOOL_NOT_FOUND` | Скажи, какой команды нет. Сам ничего не устанавливай |
| `BUILD_FILE_MISSING` | Режим `init` -> это ожидаемо, иди по режиму init. Иначе скажи: «Нет pom.xml и build.gradle: запуск не из корня проекта или проекта ещё нет - для нового проекта напишите `/orchestrator создай проект автотестов`». Правок не делай, закончи |
| `get_pvat_release_notes`: таймаут или ошибка после повтора | Запусти env_check.py без `--release-notes`, в ответе «самая новая - не сравнивалась: <ошибка>» |
| env_init.py: `НЕВЕРНО` | Покажи строку дословно, спроси значения ещё раз одной строкой |
| `REPORT_NOT_WRITTEN` | Покажи строку `ПРОБЛЕМА` дословно, правок не делай, закончи |
| `pvatf-docs` вернул `MCP НЕДОСТУПЕН` или «НЕТ В ДОКЕ» | Эту проблему не исправляй, запиши в `ENV-SETUP.md` «не исправлено: нет в документации» |
| Скрипт упал с трассировкой | Покажи последние 20 строк вывода, ничего не исправляй вручную |
