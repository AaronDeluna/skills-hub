# План автотеста по тест-кейсу

Скилл запускает `orchestrator`. Ты не пишешь код теста. Твоя работа: превратить тест-кейс в
проверенный план `.gigacode/data/autotest/<ключ>/PLAN.md`, по которому `autotest-gen` пишет
код. Почти всё делают скрипты; ты проверяешь только строки, которые скрипт пометил.
Сначала прочитай `references/autotest-rules.md` - общие правила окружения и генерации.

## Когда использовать / когда не использовать

| Просьба | Что делаешь |
|---------|-------------|
| «сгенерируй автотест по ТК <файл>», «разбери ТК» | шаги 1-7 |
| «проверь тест-кейс» (только оценка) | шаги 1-3, план не строишь |
| план уже `planned`, просят код | не этот скилл - `autotest-gen` |

## Предусловия

- Файл тест-кейса: путь от человека (`.md`, `.xml`, `.json` из TMS или Allure).
- Окружение проверено: `.gigacode/data/autotest/ENV.json` со статусом `ok` или `warning`
  (проверяет `orchestrator` до запуска этого скилла).
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).

**Скрипты лежат в `.gigacode/skills/autotest-plan/scripts/`.** Скрипта по этому пути нет ->
найди один раз: `find . ~/.gigacode -path "*autotest-plan/scripts/tc_plan.py" 2>/dev/null | head -1`.

## Шаги

1. Оркестратор передал ключ, и `.gigacode/data/autotest/<ключ>/TC.md` уже есть -> этот шаг
   пропусти. Иначе перевод ТК в единый вид (ключа в файле нет - спроси человека ключ одной строкой и добавь `--key <ключ>`):
   ```
   python3 .gigacode/skills/autotest-plan/scripts/tc_convert.py <файл ТК>
   ```
   Запомни ключ из строки `ТК:`. Дальше `<ключ>` - он.
2. Проверка ТК:
   ```
   python3 .gigacode/skills/autotest-plan/scripts/tc_check.py <ключ>
   ```
   Правила оценки и что значит каждая находка - `references/tc-rules.md`.
3. `СТАТУС: FAIL` -> покажи человеку все строки `НАХОДКА ... БЛОКИРУЕТ` и рекомендации по
   `references/tc-rules.md` (колонка «Как исправить ТК»), план не строй, закончи. Просили
   только оценку - покажи итог по шаблону и закончи.
4. Черновик плана:
   ```
   python3 .gigacode/skills/autotest-plan/scripts/tc_plan.py build <ключ>
   ```
5. Строка `ПРОВЕРИТЬ:` называет шаги с уверенностью LOW или UNKNOWN. Открой
   `references/classify.md` и исправь в `PLAN.md` только эти строки раздела 2 (тип, группа,
   технология, метка, G) и, если шаг сменил группу, - строку G в разделе 3. Причину пиши в
   колонку «Основание»: `выбрано по <маркер>`. Остальные строки не трогай.
6. Шапка плана: `package` и `test_file` равны `-` (нет ENV.json или пакета) -> возьми пакет
   у ближайшего тест-класса проекта (`grep -rh "^package" --include=*Test.java src/test | sort | uniq -c | sort -rn | head -3`);
   тестов в проекте нет - спроси человека пакет одной строкой. Константы с источником
   `UNKNOWN` - выбери источник по `references/classify.md`, раздел «Константы».
7. Проверка плана:
   ```
   python3 .gigacode/skills/autotest-plan/scripts/tc_plan.py validate <ключ>
   ```
   Каждую строку `ПРОБЛЕМА` исправь в `PLAN.md` и запусти снова. После 3 запусков с
   проблемами - покажи их человеку и закончи. `ИТОГ: план сошёлся` -> итог по шаблону.

## Контракт «вход -> выход»

Вход: путь к файлу тест-кейса; необязательно - ключ.

Выход в `.gigacode/data/autotest/<ключ>/`:
- `TC.md` - тест-кейс в едином виде (пишет tc_convert.py);
- `TC-CHECK.md` - оценка ТК (пишет tc_check.py);
- `PLAN.md` - план, `plan_status: planned` (пишет tc_plan.py, ты правишь только строки из шагов 5-6).

Ответ в чате строго по шаблону:
```
Тест-кейс: <ключ> · <название> · шагов <n>
Проверка ТК: <PASS | WARNING | FAIL> · средняя оценка <n> · блокирующих находок <n>
План: <planned | не сошёлся> · шагов генерации <n> · технологии: <группы через запятую> · констант <n>
Тест-класс: <test_file из шапки>
Исправлено вручную: <шаг - что - основание; нет - «нет»>
Дальше: «Напишите: /orchestrator продолжи генерацию <ключ>»
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| tc_convert.py: `ФОРМАТ НЕ РАСПОЗНАН` / `ШАГОВ НЕТ` | Покажи строку дословно, попроси ТК в формате `references/tc-rules.md`, раздел «Формат ТК». Дальше не иди |
| tc_plan.py build: `ПЛАН УЖЕ ЕСТЬ` | План уже утверждён - не перестраивай. Человек прямо просит перестроить -> `--force` |
| Код выхода 2 у любого скрипта | Покажи вывод, проверь, что запускаешь из корня проекта, запусти снова. Снова 2 - остановись |
| Шаг нельзя отнести ни к одной группе по `classify.md` | Группа `other`, технология `ValueService`, в «Решения и блокеры» - строка `шаг <n>: группа не определена, проверить человеку` |

## Чек-лист проверки

- [ ] При FAIL план не строился.
- [ ] В `PLAN.md` вручную изменены только строки из `ПРОВЕРИТЬ`, шапка и константы `UNKNOWN`.
- [ ] Последний `tc_plan.py validate` вывел `ИТОГ: план сошёлся`.
- [ ] Ответ в чате - по шаблону.
