# Классификация шагов и констант (ручная проверка)

Часть скилла `autotest-plan`. Открывай, только когда шаг 5 или 6 SKILL.md направил сюда.
Правишь только строки, которые назвал `ПРОВЕРИТЬ:` (уверенность LOW или UNKNOWN).

## Тип шага (колонка «Тип»)

Первый подходящий сверху - по глаголу действия:

| Тип | Признак | Пример |
|-----|---------|--------|
| `ASSERT` | проверить, убедиться, должен, содержит, совпадает | «Проверить код ответа 200» |
| `TEARDOWN_CLEANUP` | удалить созданное, очистить, закрыть сессию | «Удалить созданный заказ» |
| `NAVIGATION` | перейти, открыть страницу / раздел / экран | «Открыть раздел Платежи» |
| `AUTH_SESSION` | авторизоваться, войти, получить токен | «Войти под пользователем ADMIN» |
| `OPERATION` | отправить, выполнить, создать, изменить, нажать, ввести | «Отправить POST /orders» |
| `SETUP` | подготовить, настроить, сгенерировать данные | «Подготовить пользователя фикстурой» |
| `PRECONDITION` | состояние до теста из «Предусловий» | «Пользователь авторизован» |

## Группа и технология (колонки «Группа», «Технология», «Метка»)

Ищи маркер в действии и данных шага; два маркера разных групп - побеждает объект проверки
(«Проверить на странице, что запись появилась в БД» -> `db`).

| Группа | Технология | Метка | Маркеры |
|--------|------------|-------|---------|
| `integration` | Работа с Rest API / gRPC / GraphQL / WebSocket | `rest` / `grpc` / `graphql` / `websocket` | POST, GET, эндпоинт, `/api/`, код ответа, JSONPath; gRPC; GraphQL; ws:// |
| `db` | Работа с Базами Данных / DataSource / OpenSearch/ElasticSearch | `db` / `db` / `opensearch` | SQL, SELECT, таблица, БД; DataSource; OpenSearch, Elastic |
| `kafka` | Работа с Kafka | `kafka` | Kafka, топик, продюсер, консьюмер |
| `ui` | Работа с UI Playwright / Работа с UI Selenide | `ui` | страница, кнопка, поле, клик, браузер |
| `mobile` | Работа с Appium Android / Работа с Appium iOS | `mobile` | Android, iOS, Appium, мобильное приложение |
| `logs_metrics` | Единый Аудит / Журналы ЕФС и ППРБ / PVM-ABYSS / метрики / СУП | `audit` / `journal` / `abyss` / `metrics` / `sup` | аудит; журнал, ЕФС, ППРБ; ABYSS; Thanos, Victoria, метрика; СУП |
| `tools` | Fixtures / Таймауты / TestContainers / SberMock / OpenShift / DataConverter / Toggler / Launcher | `fixtures` / `timeouts` / `testcontainers` / `sbermock` / `openshift` / `dataconverter` / `toggler` / `launcher` | по названию сервиса |
| `other` | ValueService / Работа с Сессиями / Работа с Invocation | `value` / `session` / `invocation` | сгенерировать значение; сессия, авторизован; Invocation |

Маркеров нет - группа соседнего шага, который проверяет или готовит то же самое; в
«Основание» - `как у шага <n>: <почему>`. Предусловие «пользователь авторизован» без
маркеров - `other` / Работа с Сессиями / `session`.

## Шаги генерации (колонка «G» и раздел 3)

Новая G начинается, когда меняется группа или технология, когда UI-шаг уходит на новый экран
и после 4 шагов в одной G. Проверка результата запроса остаётся в G этого запроса. Сменил
группу шага - перенеси его в подходящую G раздела 3 (колонка «Шаги») или добавь новую строку
G со статусом `todo` и справкой `tech-<группа>.md` (`logs_metrics` -> `tech-logs-metrics.md`).

## Константы (раздел 4, колонка «Источник»)

| Значение | Источник | Форма |
|----------|----------|-------|
| адрес сервиса, хост, логин, пароль, токен, имя топика | `PROPERTIES_FILE` | `PROPERTIES_REF` |
| путь запроса, код ответа, SQL, JSONPath, ожидаемое значение, паттерн | `TEST_CLASS_STATIC_FINAL` | `LOCAL_FIELD_REF` |
| тело запроса, сообщения, файл данных | `TESTDATA_FILE_REF` | `FILE_NAME_REF` |
| значение, которое уже есть в классе констант проекта | `GLOBAL_CONSTANTS_CLASS` | `CONSTANTS_FIELD_REF` |
| значение из перечисления проекта | `ENUM` | `ENUM_VALUE_REF` |

Сгенерированные значения (`__traceId__`, «сгенерировать UUID») - не константы, а переменные
(раздел 5). Текст кнопок и полей UI - не константы: это аргументы локаторов в классе страницы.
