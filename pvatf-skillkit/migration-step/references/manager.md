# Режим менеджера: подшаг делает сабагент-исполнитель

Часть скилла `migration-step`. **Это режим по умолчанию.** Действует, если в паспорте карты
строка `- Режим исполнения: менеджер` или такой строки нет совсем (карта построена раньше).
Только при `- Режим исполнения: сам` этот файл не читаешь, подшаги делаешь сам
(`references/work.md`, `references/check.md`).

Зачем: в длинном юните `tech` твой контекст копит код всех подшагов, и к десятому подшагу
правила первых забываются. В режиме менеджера ты код не пишешь и файлы проекта не читаешь.
Каждый подшаг делает новый сабагент с чистым контекстом, получает только свой пакет и
возвращает короткий отчёт. Ты ведёшь карточку, проверяешь и коммитишь.

Режим работает, если сабагенты GigaCode умеют менять файлы проекта и запускать команды
(сборку, тесты, `java`). Это проверяется на деле, на первом подшаге - см. «Первый
исполнитель в карте».

## Первый исполнитель в карте

В паспорте карты нет пометки `проверено`, рядом с режимом -> после отчёта ПЕРВОГО
исполнителя проверь сам:
```
git status --short
```
- в выводе есть файлы подшага, а в отчёте - вывод компиляции -> сабагенты умеют всё
  нужное: допиши в строку паспорта `· проверено M-<nnn> S-<nn>` и работай дальше в этом
  режиме;
- файлов подшага в выводе нет, или исполнитель ответил, что не может менять файлы или
  запускать команды, или инструмента сабагентов нет физически -> переключись: строка
  паспорта `- Режим исполнения: сам · основание: сабагент не смог менять файлы (M-<nnn>
  S-<nn>, <что случилось одной строкой>)`. Этот подшаг и все следующие делаешь сам
  (`references/work.md`, `references/check.md`). Человека не спрашивай.

## Правила менеджера

1. **Один подшаг - один исполнитель, строго по очереди.** Следующий исполнитель
   запускается, только когда предыдущий подшаг закрыт и закоммичен. Параллельно -
   никогда: исполнители правят одни и те же файлы и собирают один проект.
2. **Ты не пишешь код и не читаешь файлы проекта целиком.** Ты читаешь карточку, карту,
   отчёты сабагентов и вывод скриптов.
3. **Карточку и карту пишешь только ты.** Исполнитель меняет только файлы своего подшага
   и `rules-now.md` не трогает.
4. **Коммит - только ты**, после проверяющего и чекпоинта.
5. **Документация - до исполнителя.** Исполнитель не может запустить сабагента
   документации (сабагент не запускает сабагентов). Поэтому всё, что ему нужно из
   документации, ты добываешь заранее и передаёшь в «Таблице подтверждений».

## Цикл подшага

Для каждого подшага по порядку (как в `references/tech-flow.md`, п.2; подшаги `разбор` и
`review` делаешь сам, как раньше):

1. **Пакет.** `Unit.java recite M-<nnn> S-<nn>` и `Unit.java rules M-<nnn> S-<nn>`. Подшагу
   статус `in-progress`.
2. **Документация.** Шаг 3 из `references/work.md`: записи подшага - в `tmp/docs-now.md`;
   каждое имя фрейма, которого там нет, сначала ищешь `Notes.java find`, и только чего нет и
   там - сабагент документации. Запиши в «Таблицу подтверждений» карточки. Нужного нет и в
   документации -> строка `решить человеку` во «Входящие», в пакет исполнителю - «это место
   не трогать».
3. **Исполнитель.** Запусти сабагента по промпту ниже. Дождись отчёта.
4. **Твоя проверка отчёта.** Отчёт не по шаблону -> запусти исполнителя заново (один раз).
   `Статус: не сделан` -> «Если упёрся» (`references/stuck.md`) по причине из отчёта.
5. **Скрипт.** `Unit.java check M-<nnn> S-<nn>`: `находок 0` -> дальше; есть находки ->
   исполнитель ещё раз с этими находками (п.8).
6. **Проверяющий.** Сабагент «проверяющий» по промпту из `references/check.md`, п.9,
   дословно. Находки `просто` -> исполнитель ещё раз (п.8); `крупно` -> дописать подшаг
   по `references/tech-flow.md`, «Дописывание подшагов».
7. **Чекпоинт подшага** - выполни команду из поля «Чекпоинт» сам. Не сошёлся ->
   исполнитель ещё раз с выводом чекпоинта (п.8).
8. **Повтор исполнителя.** Тот же промпт плюс в конце «Подшаг уже начат. Исправь ТОЛЬКО
   это, остальное не трогай:» и список находок. Повторов на подшаг - не больше двух. После
   второго находки остались -> строки `решить человеку: <файл>:<строка> - <что>` во
   «Входящие», подшаг закрывается, если проект компилируется; не компилируется -> подшаг
   `blocked`, стоп чата.
9. **Закрытие.** В «Сделано» подшага - отчёт исполнителя (строки «Сделано», «Проверки»),
   строка `проверка: ...` и вывод чекпоинта. Статус `done`, коммит файлов подшага и
   карточки (`references/tech-flow.md`, п.4). Дальше - следующий подшаг.

## Промпт сабагенту «исполнитель подшага» (копируй дословно, подставь `<...>`)

```
Ты выполняешь ОДИН подшаг миграции проекта автотестов на фрейм PVATF. Меняешь только
файлы из списка ниже. Карточку, карту и файлы в .gigacode/ не меняешь. Коммиты не делаешь.
Вопросов не задаёшь: не знаешь, как сделать место, - не трогай его и напиши в отчёте.
Всё, что пишешь о фрейме, бери только из «Таблицы подтверждений» ниже; .jar, ~/.m2,
интернет и «по памяти» - запрещено.

Проект: <абсолютный путь к корню>
Подшаг: M-<nnn> S-<nn> · <вид> · <название>
Файлы (менять можно ТОЛЬКО их):
- <путь> - <изменить / создать / удалить>
Что сделать (по порядку):
<пункты «Что сделать» подшага дословно>
Критерии по файлам:
<таблица «Критерии по файлам» дословно; нет - "-">
Итоговый результат: <дословно>
Таблица подтверждений (имена фрейма, которые можно писать):
<строки таблицы подтверждений: имя - запись конспекта - как использовать (1 строка)>
Не трогать (нет в документации): <места; нет - "-">
Образец в проекте (как уже сделано в прошлых подшагах): <1-2 пути из «Что уже изменилось»; нет - "-">

Правила кода - прочитай целиком ДО правок:
<путь>/.gigacode/data/migration/tmp/rules-now.md

Порядок:
1. Прочитай файлы из списка (только их).
2. Сделай пункты «Что сделать» по порядку. Слои: тест -> шаги предметной области ->
   базовый слой технологии -> фрейм. Без делегатов, вложенных классов, своих matchers,
   DTO ответа, вспомогательных методов в тест-классе.
3. Компиляция: <команда из паспорта>. Ошибка в твоём коде - исправь; не вышло за 3
   попытки - верни как было и напиши в отчёте.
4. Самопроверка: java -Dfile.encoding=UTF-8 .gigacode/skills/migration-step/scripts/Unit.java check M-<nnn> S-<nn>
   Исправь каждую строку вывода, пока не будет «находок 0».
5. Показательный тест: <команда с timeout 600; для env и core-new - "-">

Верни РОВНО так:
- Статус: сделан / не сделан: <причина в 1 строку>
- Сделано: <по строке на пункт «Что сделать»: номер - что сделано>
- Файлы: <путь - изменён / создан / удалён>
- Проверки: компиляция <ок / ошибка>; Unit.java check <находок n>; тест <зелёный / красный: ... / не запускался>
- Не сделано и почему: <пункт - причина; нет - "нет">
```
