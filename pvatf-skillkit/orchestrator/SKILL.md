# Оркестратор набора PVATF

Набор ведёт три процесса, состояние каждого - в файлах `.gigacode/data/`: миграция
(`migration/`), окружение и генерация автотестов (`autotest/`), плюс разметка тестов
(`markup/`). Ты сам не мигрируешь, не пишешь тесты и не правишь сборку. Твоя работа: понять,
чего хочет человек, узнать у скрипта следующее действие, запустить ОДИН скилл и коротко
отчитаться.

## Когда использовать / когда не использовать

Использовать в начале каждого чата по миграции, разметке, окружению и генерации автотестов
PVATF - даже если человек назвал скилл напрямую: состояние процесса знает только скрипт
шага 2. Не использовать для вопросов о коде, не связанных с этими процессами.

## Предусловия

- Запуск из корня проекта автотестов (там, где `.gigacode/`).
- Python 3.8+ - для скрипта шага 2.
- Агенты набора `pvatf-*` ставит сам скрипт шага 2 (после установки нужен перезапуск GigaCode).

Миграция и разметка: сначала прочитай `references/core-rules.md` - общие правила миграции.
Окружение и генерация: правила - `references/autotest-rules.md` (их читает запущенный скилл).

## Шаги

**Скрипты этого скилла лежат в `.gigacode/skills/orchestrator/scripts/`.** Команды ниже - готовые:
копируй и запускай как есть, из корня проекта (там, где `.gigacode/`); нужен
Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`). Скрипта по этому пути нет (скиллы установлены в другое место) -> найди его один
раз: `find . ~/.gigacode -path "*orchestrator/scripts/*.py" 2>/dev/null | head -3` - и подставляй
найденный каталог. Скрипт упал с ошибкой -> покажи ошибку в чате, дальше - по таблице
«Обработка ошибок»; молча пропускать скрипт нельзя.

### Шаг 1 - Чего хочет человек

Первая подходящая строка сверху:

| Просьба | Что делаешь |
|---------|-------------|
| показать статус, «что сделано» | `references/status.md`. Скиллы не запускай |
| сжать карту, «карта разрослась» | `references/compress.md`. Скиллы не запускай |
| перенести тесты из другого (старого) проекта в этот | Скажи: «Перенос из старого проекта в новый пока не поддерживается. Эти скиллы мигрируют проект на месте: целиком или только ядро». Больше ничего не делай |
| проверить или поставить разметку тестов («проверь разметку», «настрой разметку», «разметь тесты», «поставь разметку», «продолжи разметку», «поправь разметку по отчёту») | `references/markup.md`. Скиллы миграции не запускай. Шаг 2 не нужен |
| проверить миграцию («как прошла миграция») | Запусти `migration-review`. Карта не обязательна. Названные старые библиотеки передай дословно |
| только ядро / полная миграция («тесты не трогай», «теперь переводи тесты») | `references/scope.md`, потом Шаг 2 |
| проект сильно изменился, карта устарела | Запусти `migration-map`: режим обновления (Этап 6) |
| кто делает подшаги: «подшаги делай сабагентами», «режим менеджера» / «подшаги делай сам», «без сабагентов» | Карты нет -> передай просьбу в `migration-map`. Карта есть -> в разделе 1 карты замени строку на `- Режим исполнения: менеджер · основание: попросил человек` (или `сам`), скажи человеку, что режим переключён. Потом Шаг 2, если просил ещё что-то |
| ответы на вопросы карты | `references/questions.md`, п.2 |
| проверить окружение («проверь окружение», «готов ли проект», «почему не компилируется») | Шаг 2 с аргументом `env check` |
| настроить окружение («настрой окружение», «подключи фрейм», «почини окружение») | Шаг 2 с аргументом `env setup` |
| обновить окружение или фрейм («обнови окружение», «обнови фрейм», «подними версию PVATF», «продолжи обновление», «откати обновление») | Шаг 2 с аргументом `env update`. Названную версию и слово «откати» передай в `env-update` дословно |
| сгенерировать автотест по тест-кейсу, проверить или разобрать ТК («сгенерируй автотест по <файл>», «проверь тест-кейс <файл>») | Шаг 2 с аргументом `autotest <путь к файлу ТК>`; файла в просьбе нет - `autotest` |
| продолжить генерацию («продолжи генерацию», «продолжи генерацию <ключ>», «собери автотест <ключ>») | Шаг 2 с аргументом `autotest [<ключ>]` |
| проверить или оптимизировать существующий автотест («проверь автотест <файл>», «оптимизируй тест», «вынеси константы из теста», «продолжи проверку автотеста», «откати правки теста») | Шаг 2 с аргументом `review [<путь к файлу теста>]`. Слово «откати» передай в `autotest-review` дословно |
| всё остальное («мигрируй», «продолжи», «сделай M-012», «с M-001 по M-003») | Шаг 2 |

Выпиши из просьбы и передай дальше дословно: названные технологии и пути к проекту-примеру
или исходникам фрейма (их получает `migration-map`); названный юнит, диапазон или список
(их получает скрипт в Шаге 2).

### Шаг 2 - Спроси скрипт, что делать

```
python3 .gigacode/skills/orchestrator/scripts/next_action.py [M-012 | M-001..M-003 | M-001,M-004 | env <check|setup|update> | autotest [<ключ ТК> | <путь к файлу ТК>] | review [<путь к файлу теста>]]
```

Аргумент - по таблице шага 1; для миграции - только если человек назвал юнит, диапазон или
список. Скрипт читает файлы процесса и печатает `ДЕЙСТВИЕ:` и `ПОЧЕМУ:`. Ещё он ставит агентов набора (`pvatf-*`) в `.gigacode/agents/`
проекта, если их там нет или они устарели. **Шаг обязателен в каждом чате:** без вывода скрипта
скиллы не запускаешь; обе строки вывода покажи человеку дословно. Делай ровно то, что
скрипт сказал, сам юнит не выбирай:

| ДЕЙСТВИЕ | Что делаешь |
|----------|-------------|
| `агенты установлены` | Скрипт записал агентов набора в `.gigacode/agents/`. Покажи обе строки вывода и скажи: «Агенты миграции установлены или обновлены. Перезапустите GigaCode (выйдите и запустите заново) и введите, чтобы продолжить с того же места: `/orchestrator <запрос человека дословно>`». Вместо `<запрос человека дословно>` подставь текст, который человек написал после `/orchestrator` в этом сообщении, без изменений. Скиллы не запускай. Агентов сам не копируй и `.gigacode/agents/` не проверяй: скрипт уже сравнил их с установленными и записал только новые или изменённые |
| `migration-map` | Запусти `migration-map`, передай технологии, пути и ответы на вопросы, если были |
| `одобрение карты` | Покажи сводку карты и спроси «Карту утверждаем? да/нет». «Да» -> `map_status: approved` в шапке карты. Правки -> `migration-map`, Этап 6 |
| `вопросы` | `references/questions.md`. Юниты не запускай |
| `карта повреждена` | Покажи человеку причину из `ПОЧЕМУ` дословно. Скиллы не запускай: по повреждённой таблице юнитов нельзя понять, что сделано |
| `migration-step M-<nnn>` | Запусти `migration-step` на этот юнит |
| `migration-step пачка: ...` | Запусти `migration-step` ОДИН раз, передай «пачка: <ID через запятую>» |
| `нельзя`, `нечего делать` | Объясни человеку причину из `ПОЧЕМУ`, скиллы не запускай |
| `заблокировано` | Покажи блокеры: раздел «Блокер» карточек `blocked` и строки `решить человеку` (`grep -n "решить человеку" .gigacode/data/migration/MIGRATION-MAP.md`) |
| `ядро готово` | Скажи: ядро переведено, тесты не тронуты; продолжить - по просьбе о полной миграции |
| `migration-review` | Запусти `migration-review` |
| `проверка не сходится` | Покажи сводку последнего круга из `MIGRATION-REVIEW.md`, попроси человека посмотреть повторяющиеся находки. Новый круг - только по прямой просьбе |
| `финал` | `references/final.md` |
| `env-check` | Запусти `env-check`, режим `check` |
| `env-setup` | Запусти `env-check`, режим `setup`; передай путь к проекту-примеру, если человек его дал |
| `env-update` | Запусти `env-update`; передай названную версию или «откат», если были |
| `autotest-plan` | Запусти `autotest-plan`; передай путь к файлу ТК. Пути нет - спроси человека одной строкой: «Укажите путь к файлу тест-кейса (md, xml или json)» и закончи |
| `autotest-plan <ключ>` | Запусти `autotest-plan` на этот ключ (ТК уже разобран: `.gigacode/data/autotest/<ключ>/TC.md`) |
| `autotest-gen <ключ>` | Запусти `autotest-gen` на этот ключ |
| `финал <ключ>` | Покажи итог из `.gigacode/data/autotest/<ключ>/CHECK.md` (строки «Тест-класс», «Компиляция», «Находок») и предложи: «Напишите: `/orchestrator разметь тесты`» и «Напишите: `/orchestrator проверь автотест <путь из строки «Тест-класс»>`» |
| `autotest-review` | Пути нет - спроси человека одной строкой: «Укажите путь к тест-классу (.java) от корня проекта» и закончи |
| `autotest-review <файл>` | Запусти `autotest-review` на этот файл; слово «откати» из просьбы передай дословно |

Строка `ЗАМЕТКА:` -> добавь её смысл в итоговый ответ. Скрипт упал или карта не читается ->
скажи человеку, что именно вывел скрипт; сам таблицу юнитов не разбирай.

### Шаг 3 - Запусти один скилл и дождись его конца

Вызови выбранный скилл через механизм вызова скиллов. С этого момента работаешь по SKILL.md
этого скилла: его правила главнее этого файла. Когда скилл закончил - второй скилл в этом
чате не запускай.

## Контракт «вход -> выход»

Вход: сообщение человека после `/orchestrator`. Выход: две строки вывода скрипта дословно,
результат одного запущенного скилла и итоговый ответ по шаблону ниже. Файлы процессов
оркестратор не меняет, кроме шапки карты при одобрении и строки режима исполнения.

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| Скрипт шага 2 упал или вывел не `ДЕЙСТВИЕ:` | Покажи вывод дословно. Скиллы не запускай, состояние сам не разбирай |
| Скрипта нет по пути | `find` из начала файла; не нашёлся - скажи человеку переустановить набор |
| Запущенный скилл закончился ошибкой | Покажи его итог; второй скилл в этом чате не запускай |

## Чек-лист проверки

- [ ] Скрипт шага 2 запускался в этом чате, обе строки его вывода показаны человеку.
- [ ] Запущен ровно один скилл - тот, что назвал скрипт.
- [ ] Итоговый ответ - по шаблону.

## Итоговый ответ человеку

Миграция - коротко:
- что было на входе и какой скилл запущен;
- что он сделал (этап карты / юнит и его статус);
- прогресс: `done` X из N юнитов;
- что осталось на человеке (вопросы, строки `решить человеку`, пуш - без разрешения не делается);
- что дальше: **«Откройте новый чат и напишите: `/orchestrator Продолжи миграцию`»**.

Окружение и генерация - итог запущенного скилла по его шаблону и строка «Дальше» из него.
