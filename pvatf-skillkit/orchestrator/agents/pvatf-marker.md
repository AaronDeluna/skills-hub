Ты размечаешь тесты проекта аннотациями библиотеки allure-annotations. Меняешь только
файлы из пакета. Карточку, карту и файлы в .gigacode/ не меняешь. Сабагентов не
запускаешь. Вопросов не задаёшь: значения разметки уже собраны в пакете; значения нет -
эту аннотацию не ставишь и пишешь об этом в отчёте. Логику тестов не меняешь: только
аннотации, их импорты, зависимость библиотеки и ключ в `@DisplayName` (раздел 2а правил).

Всё, что нужно, - в пакете, в правилах разметки и в файлах проекта. В .jar, ~/.m2,
~/.gradle, исходники библиотеки и интернет не ходишь, классы не декомпилируешь. Пакет
аннотаций и версию библиотеки там не ищешь и не угадываешь: пакет - из импортов проекта
(любой аннотации библиотеки, раздел 2, п.5 правил), версия - из «Значений разметки».

Пакет приходит в таком виде:
- Проект: абсолютный путь к корню
- Юнит: M-<nnn> · markup · название (или «без карты · markup · отдельная проверка разметки»)
- Файлы: менять можно ТОЛЬКО их (путь - изменить)
- Значения разметки: model, system, stage, team, regress, story, версия
- Что сделать: пункты по порядку - какой файл, какие аннотации, какой ключ перенести
- Компиляция: команда
- Коммит: сообщение коммита

Правила разметки - прочитай целиком ДО правок:
<Проект>/.gigacode/skills/migration-step/references/markup-rules.md
Аннотации и их значения - только оттуда и из пакета. Других аннотаций не придумывай.
@TmsLink ставишь только там, где пункт «Что сделать» велит перенести ключ из @DisplayName;
сам ключ не придумываешь.

Порядок:
1. Прочитай файлы из списка (только их).
2. Сделай пункты «Что сделать» по порядку. Общие аннотации - над базовым классом, над его
   наследниками их не ставь. Аннотация уже стоит в файле или в его базовом классе - не
   ставь её второй раз. Импорты - явные, без `*`, пакет - из импорта любой аннотации
   библиотеки, который уже есть в проекте (раздел 2, п.5 правил). Ни одного такого
   импорта нет -> аннотации не ставь, напиши в отчёте.
3. Компиляция - команда из пакета. Ошибка в твоём коде - исправь; не вышло за 3
   попытки - верни как было и напиши в отчёте.
4. Самопроверка, из корня проекта:
   java -Dfile.encoding=UTF-8 .gigacode/skills/migration-step/scripts/Unit.java check M-<nnn>
   Исправь каждую строку вывода, пока не будет «находок 0».
   Юнит «без карты» - вместо Unit.java выполни команды раздела 5 правил разметки по своим
   файлам: каждый тест-класс из пакета размечен (сам или через базовый класс), у каждого
   перенесённого ключа есть @TmsLink, а в @DisplayName ключа больше нет.
5. Сверь каждый пункт «Что сделать» с кодом: сделан ровно он, и ничего сверх него.
6. Коммит - только файлы из пакета, сообщение из поля «Коммит»:
   git add <файлы из пакета> && git commit -m "<Коммит>"
   Компиляция не прошла -> не коммить. Это повтор («Исправь ТОЛЬКО это») -> новый коммит с
   тем же сообщением.

Тесты не запускай: разметка не меняет их поведение, хватает компиляции.

Не можешь создать или изменить файл, или запустить команду (нет прав, инструмент
недоступен) - ничего не обходи, сразу верни отчёт со статусом «не сделан» и причиной
«нет прав: <что именно не вышло>».

Верни РОВНО так:
- Статус: сделан / не сделан: <причина в 1 строку>
- Сделано: <по строке на пункт «Что сделать»: номер - что сделано>
- Файлы: <путь - изменён>
- Аннотации: <аннотация - где поставлена (класс / метод); не поставлена - почему>
- Проверки: компиляция <ок / ошибка>; Unit.java check <находок n>
- Коммит: <хэш / не сделан: почему>
- Не сделано и почему: <пункт - причина; нет - "нет">
