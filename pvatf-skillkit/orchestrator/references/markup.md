# Отдельная проверка разметки

Открывай, когда человек просит проверить или поставить разметку тестов, а не мигрировать
проект: «проверь разметку», «разметь тесты», «поставь разметку», «настрой разметку», «продолжи
разметку», «поправь разметку по отчёту».

Как устроено - как миграция, только для разметки:
1. **вопросы** человеку - сразу, до любого анализа (раздел 2);
2. **анализ** - отдельный агент `pvatf-markup-analyst` пишет карту разметки: что у каждого
   тест-класса есть, чего нет, что не сходится с ответами, план по частям (раздел 3);
3. **расхождения** - вопросы по тому, что не сошлось, и анализ заново (раздел 4);
4. **разметка** - агент `pvatf-marker` по карте, часть за частью (раздел 5);
5. **проверка** скриптом - каждый тест-класс (раздел 6).

Что делать по просьбе:
- «проверь разметку» - разделы 1, 3 (режим `проверка`), 7. Вопросов нет, правок нет;
- «разметь тесты», «поставь разметку», «настрой разметку» - разделы 1-7;
- «продолжи разметку» - раздел 5 с первой части, где есть `[ ]`, потом 6-7;
- «поправь разметку по отчёту», «исправь разметку» - раздел 8.
Скиллы миграции не запускаешь, карту миграции не создаёшь и не меняешь. Это не миграция:
вопросы человеку здесь задаются по ходу (правило 8 `references/core-rules.md` относится к
миграции).

Правила разметки - `references/markup-rules.md`. Прочитай его целиком до первой команды.
Карта разметки (отчёт) - `.gigacode/data/markup/MARKUP-REPORT.md`; разметка каждого тест-класса -
`.gigacode/data/markup/MARKUP-CLASSES.txt`. Пишет их агент анализа. Ты в отчёте меняешь только:
раздел «Значения разметки», строки `Ответ:` в «Расхождениях», колонку «Сделано» плана и
раздел «Итог».

**Где искать - только в проекте** (раздел 0 правил разметки). Не выходи за корень проекта,
не ходи в проект и исходники фреймворка, проект-пример, `~/.m2`, `~/.gradle`, .jar и интернет.

## 1. Подготовка

1. Агенты: выполни `python3 .gigacode/skills/orchestrator/scripts/next_action.py`.
   `ДЕЙСТВИЕ: агенты установлены` -> скажи «Агенты установлены или обновлены. Перезапустите
   GigaCode (выйдите и запустите заново) и введите, чтобы продолжить с того же места:
   `/orchestrator <запрос человека дословно>`» и закончи. Вместо `<запрос человека
   дословно>` подставь текст, который человек написал после `/orchestrator`, без изменений.
   Любое другое действие к этой просьбе не относится: не выполняй его и не показывай.
   Агентов сам не копируй и `.gigacode/agents/` не проверяй: это делает скрипт.
2. Идёт ли миграция: есть `.gigacode/data/migration/MIGRATION-MAP.md` и в его таблице юнитов
   есть юнит `markup` не в статусе `done` -> разметку поставит миграция. Просили поставить ->
   скажи «Разметку поставит шаг миграции M-<nnn>: `/orchestrator Продолжи миграцию`» и
   закончи. Просили проверить -> делай проверку.
3. Тесты есть:
   `find . -type d \( -path "*/src/test/java" -o -path "*/src/test/kotlin" \) | grep -v "/target/\|/build/\|\.gigacode"`,
   в них `grep -rlE "@(Test|ParameterizedTest)\b" --include='*.java' --include='*.kt' <каталог> | head -1`.
   Пусто -> скажи «В проекте не нашлось тестов для разметки» и закончи.
4. Просили поставить -> git: `git status --porcelain -- . ':(exclude).gigacode'` не пустой ->
   скажи «В проекте есть незакоммиченные изменения: <файлы из вывода>. Закоммитьте их, и я
   продолжу разметку» и закончи. Это до вопросов, чтобы человек не отвечал зря.
5. `mkdir -p .gigacode/data/markup`.

## 2. Вопросы - первым делом, до анализа

Ничего в проекте не ищи и не сканируй, пока не получил все ответы. Даже если аннотации в
проекте уже стоят - всё равно спрашивай: что не сойдётся с проектом, сверит анализ.

1. Скажи: «Для разметки нужны значения: команда, КЭ, контур и где хранится тестовая модель.
   Задам вопросы по одному».
2. Вопросы - из таблицы раздела 4 правил, их текстом, строго в этом порядке, по одному:
   1. `teams` - одна команда или несколько;
   2. `team` - `одна`: первый текст (название); `несколько`: второй текст (какие команды и
      чьи тесты);
   3. `fos` - только при `teams: одна`, первый текст. Ответ не похож на ФОС
      (`[0-9]{2}[a-zA-Z][a-zA-Z0-9][0-9]+`) -> повтори один раз;
   4. `system` - первый текст. Человек может назвать несколько КЭ - запиши все;
   5. `stage`;
   6. `model`;
   7. `regress` и `story` - только при `model: testops`.
   Как задавать - раздел 4 правил, «Как задавать»: варианты - только настоящие значения;
   пунктов «укажу своё значение», «другое» не добавляй - поле для своего ответа в окне вопроса
   есть всегда. Свободный ответ (команда, ФОС, КЭ, задача) - без вариантов, в конце текста
   «Укажите в поле ввода.».
3. **Сверка перед анализом.** У каждого ключа есть значение: `teams`, `team`, `fos` (или
   `не нужно: команд несколько`), `system`, `stage`, `model`, `regress`, `story` (или `не
   нужно: модель не в Allure TestOps`). Чего-то нет -> задай этот вопрос сейчас. Чаще всего
   забывают `fos`, `system` и `stage` - проверь их первыми.
4. Запиши ответы в отчёт. Отчёт создаётся заново - только этот раздел, остальное напишет
   агент анализа:
   ```
   # Карта разметки

   ## Значения разметки
   - teams: <одна / несколько>
   - team: <команда (ФОС) - одна команда / <команда> - <тесты>; ... - несколько, без ФОС / ->
   - fos: <ФОС / не нужно: команд несколько / ->
   - system: <КЭ / КЭ, КЭ, ... / ->
   - stage: <code / dev / st / ift / psi / prom / ->
   - model: <testops / tms: <название>>
   - regress: <regress / critical / - / не нужно: модель не в Allure TestOps>
   - story: <задача / - / не нужно: модель не в Allure TestOps>
   - версия: <пусто до анализа>
   ```
   `team` при одной команде - ровно `<команда> (<ФОС>)`: название, пробел, ФОС в круглых
   скобках. Ответ `-` - эту аннотацию не ставят.

## 5. Разметка - агент `pvatf-marker`, по частям

Одна часть плана - один запуск агента и один коммит. Так агент не теряет аннотации на большом
проекте. Части - по порядку, с первой, где в колонке «Сделано» есть `[ ]`.

Для каждой части:
1. Git: `git status --porcelain -- . ':(exclude).gigacode'` не пустой -> скажи «В проекте есть
   незакоммиченные изменения: <файлы>. Закоммитьте их, и я продолжу разметку» и закончи.
2. База: `git rev-parse HEAD` - запомни хэш.
3. Команда компиляции: есть `pom.xml` -> `./mvnw -q test-compile` (нет `mvnw` -> `mvn -q
   test-compile`); есть `build.gradle` или `build.gradle.kts` -> `./gradlew testClasses`
   (нет `gradlew` -> `gradle testClasses`).
4. Запусти `pvatf-marker` по имени:
   ```
   Проект: <абсолютный путь>
   Юнит: без карты · markup · часть <k> из <N>
   Карта разметки: .gigacode/data/markup/MARKUP-REPORT.md, раздел «План разметки», часть <k>
   Файлы: <путь - изменить, по строке на каждую строку части>
   Значения разметки: <строки раздела «Значения разметки» отчёта и ответы «Расхождений», как есть>
   Что сделать: <строки части по порядку, целиком: # - файл - класс - что поставить>
   Нужно у тест-классов (--need): <ключи, как в строке «Разметка каждого тест-класса» отчёта>
   Компиляция: <команда>
   Коммит: markup: разметка тестов allure-annotations, часть <k> из <N>
   ```
   «Что сделать» - строки плана ровно как в отчёте, без сокращений. Агент вернул «не сделан»
   по проверкам перед правками (раздел 2б правил) -> не делай разметку сам и не повторяй
   агента; скажи человеку причину словами (незакоммиченные изменения / версия ниже 2.x /
   проект не компилируется / не построилось дерево зависимостей, с первыми строками ошибки),
   запиши в «Итог» и закончи. Вызов сабагента вернул ошибку (агент не запустился) -> покажи
   её в чате и сделай строки части сам, по разделам 2-3 правил, начав с проверок раздела 2б.
5. **Проверь часть сам**, не по отчёту агента:
   - отчёт агента - блок `=== ОТЧЁТ PVATF-MARKER ===` целиком; у КАЖДОЙ строки части в
     «Строки плана» - `сделано` или `не сделано: <причина>`. Строка без того и другого ->
     повтор: «Верни отчёт по шаблону: по каждой строке плана - сделано или причина»;
   - по каждой строке: `grep -n` каждой аннотации из «Что поставить» в её файле - есть;
   - `git diff --name-only <база> -- . ':(exclude).gigacode'` - только файлы части и
     `добавлен по перепроверке`; `git diff <база>` - только аннотации, импорты, зависимость
     (и `исправить` из плана); `@DisplayName` и логика тестов не тронуты;
   - компиляция - команда из п.3.
   Строка выполнена -> в отчёте в «Сделано» `[x]`. Агент написал причину -> `[!] <причина>`.
   Аннотации нет, а причины нет -> один повтор `pvatf-marker` с этими строками: «Поставь
   ТОЛЬКО это: <строки>». Снова нет -> `[!] агент не поставил, причину не назвал` и верни
   файлы части к базе: `git reset -q <база> && git checkout -- <файлы части>`; дальше не
   иди, раздел 7.
6. Коммит делает агент. `git status --porcelain` по файлам части не пустой -> `git add <файлы
   части и «добавлен по перепроверке»> && git commit -m "<Коммит>"`. Отчёт в `.gigacode/` не
   коммить. Push - только по прямой просьбе.
7. Следующая часть. Частей больше 3 -> после каждой третьей скажи человеку, сколько частей
   сделано, и продолжай, не спрашивая.
