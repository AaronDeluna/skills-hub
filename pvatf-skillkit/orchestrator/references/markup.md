# Отдельная проверка разметки

Открывай, когда человек просит проверить или поставить разметку тестов, а не мигрировать
проект: «проверь разметку», «разметь тесты», «поставь разметку». Скиллы миграции не
запускаешь, карту миграции не создаёшь и не меняешь. Это не миграция: вопросы человеку
здесь задаются по ходу (правило 8 `references/core-rules.md` относится к миграции).

Правила разметки - `references/markup-rules.md`. Прочитай его целиком до первой команды.
Отчёт - `.gigacode/data/markup/MARKUP-REPORT.md`, каждый запуск переписывает его заново.

Всё, что нужно, - в правилах разметки и в проекте. В .jar, `~/.m2`, `~/.gradle`, исходники
библиотеки allure-annotations и интернет не ходи; пакет аннотаций и версию не ищи там и не
угадывай.

## 1. Подготовка

1. Агенты: выполни `java -Dfile.encoding=UTF-8 .gigacode/skills/orchestrator/scripts/NextAction.java`.
   `ДЕЙСТВИЕ: агенты установлены` -> скажи «Агенты установлены или обновлены. Перезапустите
   GigaCode (выйдите и запустите заново) и повторите запрос» и закончи. Любое другое
   действие к этой просьбе не относится: не выполняй его и не показывай. Агентов сам не
   копируй и `.gigacode/agents/` не проверяй: это делает скрипт.
2. **Зависимость и версия - первым делом.** Выполни команду «Зависимость и версия» из
   раздела 5 правил. Версия записана свойством -> найди его значение
   командой оттуда же. Запомни: `есть <версия> (<файл>)` или `нет`. Нет -> версия для
   значений разметки - `2.0.2`.
3. Идёт ли миграция: есть `.gigacode/data/migration/MIGRATION-MAP.md` и в его таблице юнитов
   есть юнит `markup` не в статусе `done` -> разметку поставит миграция. Проверку (раздел 2)
   сделай, а план и правки (разделы 4-5) - нет: в итоге скажи «Разметку поставит шаг
   миграции M-<nnn>: `/orchestrator Продолжи миграцию`».
4. Каталоги тестов:
   `find . -type d \( -path "*/src/test/java" -o -path "*/src/test/kotlin" \) | grep -v "/target/\|/build/\|\.gigacode"`.
   Тест-классы - файлы с тестами:
   `grep -rlE "@(Test|ParameterizedTest)\b" --include='*.java' --include='*.kt' <каталог>`.
   Тест-классов нет -> скажи «В проекте не нашлось тестов для разметки» и закончи.

## 2. Проверка

1. Выполни команды раздела 5 правил по каждому каталогу тестов, включая поиск ключей в
   `@DisplayName`.
2. Для каждого тест-класса найди базовый класс
   (`grep -nE "class [A-Za-z0-9_]+.* extends [A-Za-z0-9_]+" <файл>`) и его файл
   (`grep -rl "class <Имя>\b" <каталог>`), до трёх уровней наследования. Запомни, кто от
   кого наследуется: это нужно для плана (раздел 4).
3. Для каждого тест-класса и каждой аннотации набора агента (раздел 1 правил): класс есть в
   выводе команды -> размечен сам. Нет -> проверь его базовые классы так же. Ни сам, ни
   предки не размечены -> аннотации нет.
4. `@Regress`/`@CriticalRegress` и `@Story`/`@Issue` нужны только при модели в Allure
   TestOps. Модель ещё не известна -> в отчёте эти строки с пометкой «только для Allure
   TestOps» и в итог «размечен / не размечен» не входят, пока нет ответа на `model`.
5. Ключи в `@DisplayName`: каждую найденную строку проверь по условиям раздела 2а правил.
   Все условия выполнены -> `перенести`; хоть одно нет -> `не уверен: <какое условие>`.
6. Запиши отчёт `.gigacode/data/markup/MARKUP-REPORT.md` ровно по шаблону:
   ```
   # Проверка разметки
   Дата: <ГГГГ-ММ-ДД>
   Каталоги тестов: <пути через запятую>
   Тест-классов: <N> · тест-методов: <N> · с @TmsLink: <N>
   Зависимость allure-annotations: <есть <версия> (<файл>) / нет>
   Базовые классы: <базовый класс - сколько тест-классов от него наследуется; нет - "нет">

   ## Набор агента
   | Аннотация | Размечено тест-классов | Без неё |
   |-----------|------------------------|---------|
   | контур - @TestStage | <n> из <N> | <классы через запятую / -> |
   | слой - @TestLayer | <n> из <N> | <...> |
   | КЭ - @System | <n> из <N> | <...> |
   | команда - @Team | <n> из <N> | <...> |
   | регресс - @Regress (только для Allure TestOps) | <n> из <N> | <...> |
   | задача - @Story / @Issue (только для Allure TestOps) | <n> из <N> | <...> |

   ## TMS-link
   Ключи в @DisplayName - перенесёт агент: <N>
   | Тест-метод | Ключ | Решение |
   |------------|------|---------|
   | <Класс.метод> | <ключ> | <перенести / не уверен: условие n> |
   Тест-методов без @TmsLink и без ключа - ставите вы: <N>
   Тест-классы без @TmsLink: <классы / ->

   ## Значения разметки
   <пусто до раздела 3>

   ## План разметки
   <пусто до раздела 4>

   ## Итог
   <размечен / не размечен: каких аннотаций не хватает, сколько ключей перенести>
   ```
   Без неё больше 15 классов или ключей больше 15 -> первые 15 и «и ещё <n>».
7. Покажи человеку таблицу набора агента, раздел про TMS-link и итог.
   - Размечен и переносить нечего -> закончи: итоговый ответ (раздел 6).
   - Не размечен или есть ключи `перенести`, а просили только проверить -> спроси
     «Поставить недостающие аннотации и перенести ключи из @DisplayName? да/нет».
     «нет» -> итоговый ответ. «да» -> раздел 3.
   - Не размечен или есть ключи `перенести`, просили поставить -> раздел 3.

## 3. Значения

Нужны только для аннотаций, которых не хватает. По каждому ключу раздела 4 правил:
1. Поищи значение в проекте: аннотации, настройки, README, Jenkinsfile
   (`grep -rniE "CI0[0-9]{7}|@Team|team|testops|zephyr|allure" --include='*.md' --include='*.properties' --include='*.yml' --include='Jenkinsfile*' . | grep -v "/target/\|/build/\|\.gigacode" | head`).
   Нашёл -> бери с пометкой `из проекта: <файл>`.
2. Не нашёл -> спроси человека. Перед первым вопросом скажи: «Для разметки нужны значения,
   которых нет в проекте. Задам несколько вопросов по одному». Вопросы задавай по правилам
   раздела 4 правил: по одному, в порядке таблицы, обычным сообщением, ровно текстом из
   колонки «Вопрос», без своих пояснений и вариантов. Ответ на `model` убирает вопросы
   `regress` и `story`, если модель не в Allure TestOps.
3. Версия - из раздела 1, п.2: `версия: есть в сборке <версия>` или `версия: 2.0.2`.
4. Запиши в раздел «Значения разметки» отчёта одну строку:
   `model: <testops / tms: название> · system: <КЭ / -> · stage: <контур / -> · team: <команда / -> · regress: <regress / critical / -> · story: <задача / -> · версия: <...>`.
   Ответ `-` - эту аннотацию не ставят.

## 4. План разметки

До правок составь план и запиши его в раздел «План разметки» отчёта. По нему работает агент
и по нему же ты потом проверяешь результат.

1. Разложи аннотации по правилам раздела 2 правил:
   - общие для всех тестов (`@System`, `@Team`, `@TestStage`, общие `@Regress` и `@Story`)
     -> над базовым классом из раздела 2, п.2. Тест-классы наследуются от разных базовых
     классов -> строка на каждый базовый класс. Тест-класс без базового класса -> над ним;
   - `@TestLayer` -> над тест-классом или над базовым классом слоя (раздел 3 правил);
   - ключи `перенести` -> `@TmsLink` над тест-методом и правка его `@DisplayName`;
   - зависимости нет -> файлы сборки.
   Аннотация уже стоит (сам класс или предок) -> в план не входит.
2. Запиши план таблицей, строка на файл:
   ```
   | # | Файл | Что сделать | Правило | Сделано |
   |---|------|-------------|---------|---------|
   | 1 | <путь> | <аннотации со значениями / какой ключ перенести из какого метода / зависимость с версией> | <раздел правил: 2.1 / 2.2 / 2а / 2.6> | [ ] |
   ```
3. Сверь план с правилами, пока не отправил агенту:
   - общие аннотации стоят над базовым классом и ни в одной строке не повторяются над
     его наследниками;
   - в плане нет аннотаций, которые уже стоят в классе или его предке;
   - каждый ключ из плана - со статусом `перенести` в отчёте;
   - `@TmsLink` нет нигде, кроме строк с переносом ключа;
   - значение `-` -> этой аннотации в плане нет;
   - пакет аннотаций найден в проекте (раздел 2, п.5 правил: импорт любой аннотации
     библиотеки). Не найден -> убери аннотации из плана и запиши в итог отчёта
     `не поставлено: пакет аннотаций не найден в проекте`.
   Нашёл ошибку -> исправь план и сверь заново.

## 5. Правки

1. Git: `git status --porcelain` не пустой -> скажи «В проекте есть незакоммиченные
   изменения. Закоммитьте или отложите их (git stash) и повторите запрос» и закончи.
2. База: `git rev-parse HEAD` - запомни хэш. По нему ты проверяешь правки, даже если
   агент уже закоммитил.
3. Команда компиляции: есть `pom.xml` -> `./mvnw -q test-compile` (нет `mvnw` -> `mvn -q
   test-compile`); есть `build.gradle` или `build.gradle.kts` -> `./gradlew testClasses`
   (нет `gradlew` -> `gradle testClasses`).
4. Запусти агента `pvatf-marker` по имени (правило 7 `references/core-rules.md`) с заданием:
   ```
   Проект: <абсолютный путь>
   Юнит: без карты · markup · отдельная проверка разметки
   Файлы: <путь - изменить, по строке на файл из плана>
   Значения разметки: <строка из раздела «Значения разметки» отчёта>
   Что сделать: <строки плана по порядку: номер - файл - что сделать>
   Компиляция: <команда>
   Коммит: markup: разметка тестов allure-annotations
   ```
   Вызов сабагента вернул ошибку -> покажи её в чате и сделай строки плана сам, по разделам
   2-3 правил, потом закоммить так же.
5. Проверь результат сам, по каждой строке плана:
   - `git diff --name-only <база>` и `git status --porcelain` - изменены только файлы плана;
   - `git diff <база>` - добавлены только аннотации, их импорты, зависимость и ключи убраны
     из `@DisplayName`; логика тестов не тронута;
   - компиляция - команда из п.3;
   - раздел 2, пп.1-3 заново: каждый тест-класс размечен набором агента, у каждого
     перенесённого ключа есть `@TmsLink`;
   - сверка из раздела 4, п.3 - теперь по коду, а не по плану.
   Строка плана выполнена -> в колонке «Сделано» `[x]`. Что-то не так -> один повтор
   `pvatf-marker` со списком невыполненных строк. Не вышло и во второй раз -> верни проект
   к базе (`git reset --hard <база>`: до правок рабочее дерево было чистым, п.1), запиши
   причину в итог отчёта, итоговый ответ.
6. Коммит делает агент. После проверки `git status --porcelain` по файлам плана не пустой
   (агент не закоммитил или ты правил сам) -> `git add <файлы плана> && git commit -m
   "markup: разметка тестов allure-annotations"`. Отчёт в `.gigacode/` не коммить. Push -
   только по прямой просьбе человека.
7. Обнови отчёт по разделу 2, п.6 (значения и план - те же, в плане отметки «Сделано»).

## 6. Итоговый ответ

Коротко:
- размечен ли проект: таблица набора агента «было -> стало»;
- что поставлено и где (базовый класс, тест-классы), сколько ключей перенесено из
  `@DisplayName`, коммиты (`git log --oneline <база>..HEAD`);
- значения: какие взяты из проекта, какие ответил человек;
- работа человека: тест-методы без `@TmsLink` и без ключа в названии, ключи `не уверен` -
  их ставите вы;
- отчёт: `.gigacode/data/markup/MARKUP-REPORT.md`.
