# Отдельная проверка разметки

Открывай, когда человек просит проверить или поставить разметку тестов, а не мигрировать
проект: «проверь разметку», «разметь тесты», «поставь разметку». Скиллы миграции не
запускаешь, карту миграции не создаёшь и не меняешь. Это не миграция: вопросы человеку
здесь задаются по ходу (правило 8 `references/core-rules.md` относится к миграции).

Правила разметки - `references/markup-rules.md`. Прочитай его целиком до первой команды.
Отчёт - `.gigacode/data/markup/MARKUP-REPORT.md`, каждый запуск переписывает его заново.

## 1. Подготовка

1. Агенты: выполни `java -Dfile.encoding=UTF-8 .gigacode/skills/orchestrator/scripts/NextAction.java`.
   `ДЕЙСТВИЕ: агенты установлены` -> скажи «Агенты установлены или обновлены. Перезапустите
   GigaCode (выйдите и запустите заново) и повторите запрос» и закончи. Любое другое
   действие к этой просьбе не относится: не выполняй его и не показывай.
2. Идёт ли миграция: есть `.gigacode/data/migration/MIGRATION-MAP.md` и в его таблице юнитов
   есть юнит `markup` не в статусе `done` -> разметку поставит миграция. Проверку (раздел 2)
   сделай, а правки (раздел 4) - нет: в итоге скажи «Разметку поставит шаг миграции
   M-<nnn>: `/orchestrator Продолжи миграцию`».
3. Каталоги тестов:
   `find . -type d \( -path "*/src/test/java" -o -path "*/src/test/kotlin" \) | grep -v "/target/\|/build/\|\.gigacode"`.
   Тест-классы - файлы с тестами:
   `grep -rlE "@(Test|ParameterizedTest)\b" --include=*.java --include=*.kt <каталог>`.
   Тест-классов нет -> скажи «В проекте не нашлось тестов для разметки» и закончи.

## 2. Проверка

1. Выполни команды раздела 5 правил по каждому каталогу тестов.
2. Для каждого тест-класса и каждой аннотации набора агента (раздел 1 правил): класс есть в
   выводе команды -> размечен сам. Нет -> найди базовый класс
   (`grep -nE "class [A-Za-z0-9_]+.* extends [A-Za-z0-9_]+" <файл>`), его файл
   (`grep -rl "class <Имя>\b" <каталог>`) и проверь его так же, до трёх уровней наследования.
   Ни сам, ни предки не размечены -> аннотации нет.
3. `@Regress`/`@CriticalRegress` и `@Story`/`@Issue` нужны только при модели в Allure
   TestOps. Модель ещё не известна -> в отчёте эти строки с пометкой «только для Allure
   TestOps» и в итог «размечен / не размечен» не входят, пока нет ответа на `model`.
4. Запиши отчёт `.gigacode/data/markup/MARKUP-REPORT.md` ровно по шаблону:
   ```
   # Проверка разметки
   Дата: <ГГГГ-ММ-ДД>
   Каталоги тестов: <пути через запятую>
   Тест-классов: <N> · тест-методов: <N> · с @TmsLink: <N>
   Зависимость allure-annotations: <есть <версия> / нет>

   ## Набор агента
   | Аннотация | Размечено тест-классов | Без неё |
   |-----------|------------------------|---------|
   | контур - @TestStage | <n> из <N> | <классы через запятую / -> |
   | слой - @TestLayer | <n> из <N> | <...> |
   | КЭ - @System | <n> из <N> | <...> |
   | команда - @Team | <n> из <N> | <...> |
   | регресс - @Regress (только для Allure TestOps) | <n> из <N> | <...> |
   | задача - @Story / @Issue (только для Allure TestOps) | <n> из <N> | <...> |

   ## TMS-link - ставит человек
   Тест-методов без @TmsLink: <N - с @TmsLink>
   Тест-классы без @TmsLink: <классы / ->

   ## Значения разметки
   <пусто до раздела 3>

   ## Итог
   <размечен / не размечен: каких аннотаций не хватает>
   ```
   Без неё больше 15 классов -> первые 15 и «и ещё <n>».
5. Покажи человеку таблицу набора агента, строку про TMS-link и итог.
   - Размечен -> закончи: итоговый ответ (раздел 5).
   - Не размечен, просили только проверить -> спроси «Поставить недостающие аннотации?
     да/нет». «нет» -> итоговый ответ. «да» -> раздел 3.
   - Не размечен, просили поставить -> раздел 3.

## 3. Значения

Нужны только для аннотаций, которых не хватает. По каждому ключу раздела 4 правил:
1. Поищи значение в проекте: аннотации, настройки, README, Jenkinsfile
   (`grep -rniE "CI0[0-9]{7}|@Team|team|testops|allure" --include=*.md --include=*.properties --include=*.yml --include=Jenkinsfile* . | grep -v "/target/\|/build/\|\.gigacode" | head`).
   Нашёл -> бери с пометкой `из проекта: <файл>`.
2. Не нашёл -> спроси человека. Перед первым вопросом скажи: «Для разметки нужны значения,
   которых нет в проекте. Задам несколько вопросов по одному». Вопросы - по одному, в порядке
   таблицы раздела 4 правил, текстом из колонки «Вопрос». Ответ на `model` убирает вопросы
   `regress` и `story`, если модель не в Allure TestOps.
3. Зависимость `allure-annotations` в сборке есть -> `версия: есть в сборке <версия>`;
   нет -> `версия: 2.0.2`.
4. Запиши в раздел «Значения разметки» отчёта одну строку:
   `model: <tms / testops> · system: <КЭ / -> · stage: <контур / -> · team: <команда / -> · regress: <regress / critical / -> · story: <задача / -> · версия: <...>`.
   Ответ `-` - эту аннотацию не ставят.

## 4. Правки

1. Git: `git status --porcelain` не пустой -> скажи «В проекте есть незакоммиченные
   изменения. Закоммитьте или отложите их (git stash) и повторите запрос» и закончи.
2. Составь пакет: файлы (базовый тест-класс для общих значений, тест-классы, которым нужен
   свой слой, файлы сборки без зависимости) и «Что сделать» - по пункту на файл: какие
   аннотации и с какими значениями. Каскад - раздел 2 правил. `@TmsLink` в пакет не входит.
3. Команда компиляции: есть `pom.xml` -> `./mvnw -q test-compile` (нет `mvnw` -> `mvn -q
   test-compile`); есть `build.gradle` или `build.gradle.kts` -> `./gradlew testClasses`
   (нет `gradlew` -> `gradle testClasses`).
4. Запусти агента `pvatf-marker` по имени (правило 7 `references/core-rules.md`) с заданием:
   ```
   Проект: <абсолютный путь>
   Юнит: без карты · markup · отдельная проверка разметки
   Файлы: <путь - изменить, по строке на файл>
   Значения разметки: <строка из раздела «Значения разметки» отчёта>
   Что сделать: <пункты по порядку>
   Компиляция: <команда>
   ```
   Вызов сабагента вернул ошибку -> покажи её в чате и сделай пункты сам, по разделам 2-3
   правил.
5. Проверь результат сам:
   - `git status --porcelain` - изменены только файлы пакета;
   - `git diff` - добавлены только аннотации, их импорты и зависимость; логика тестов не
     тронута;
   - компиляция - команда из п.3;
   - раздел 2, пп.1-2 заново: каждый тест-класс размечен набором агента.
   Что-то не так -> один повтор `pvatf-marker` со списком того, что не так. Не вышло и во
   второй раз -> верни файлы (`git checkout -- <файлы>`), запиши причину в итог отчёта,
   итоговый ответ.
6. Обнови отчёт по разделу 2, п.4 (значения - те же). Закоммить:
   `git add <файлы пакета> && git commit -m "markup: разметка тестов allure-annotations"`.
   Отчёт в `.gigacode/` не коммить. Push - только по прямой просьбе человека.

## 5. Итоговый ответ

Коротко:
- размечен ли проект: таблица набора агента «было -> стало»;
- что поставлено и где (базовый класс, тест-классы), коммит;
- значения: какие взяты из проекта, какие ответил человек;
- работа человека: тест-методы без `@TmsLink` - ключи ручных тестов из TMS, их ставите вы;
- отчёт: `.gigacode/data/markup/MARKUP-REPORT.md`.
