# Проверка и оптимизация существующего автотеста

Скилл запускает `orchestrator`. Находки ищет скрипт, литералы в константы выносит скрипт,
остальные правки делает агент `pvatf-generator`, компилирует и откатывает скрипт. Ты ведёшь
цикл по правкам. Состояние - в `REVIEW-PLAN.md` (`review_status` и колонка «Статус»), поэтому
оборванный чат продолжается с того же места. Сначала прочитай `references/autotest-rules.md`.

## Когда использовать / когда не использовать

| `review_status` в `.gigacode/data/autotest-review/<класс>/REVIEW-PLAN.md` | Что делаешь |
|-------------------------------------------------------------------------|-------------|
| файла нет | шаги 1-8 |
| `found` | шаги 2-8 |
| `approved` | шаги 3-8 |
| `fixing` | шаги 4-8 |
| `checked`, `rolled-back` | только итог по шаблону из `REVIEW.md`; новая проверка - шаг 1 по просьбе человека |

Тест по тест-кейсу ещё не написан - не этот скилл, а `autotest-plan`.

## Предусловия

- Путь к тест-классу `.java` от корня проекта (в классе есть `@Test`).
- `.gigacode/data/autotest/ENV.json` со статусом `ok` или `warning` - от `env-check`.
- Агенты `pvatf-generator`, `pvatf-docs` в `.gigacode/agents/` (ставит `orchestrator`).
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).

**Скрипт - `.gigacode/skills/autotest-review/scripts/review.py`.** Нет по этому пути -> найди
один раз: `find . ~/.gigacode -path "*autotest-review/scripts/review.py" 2>/dev/null | head -1`.

## Шаги

1. Находки и план:
   ```
   python3 .gigacode/skills/autotest-review/scripts/review.py find <файл>
   ```
   Код 1 и `НАХОДОК: 0` -> итог «находок нет», дальше не идёшь.
2. Спроси человека - покажи строки находок из вывода (R, тип, где, что сделать, кто,
   зависимые тесты) и задай ровно один вопрос:
   «Какие правки делать: все / никакие / номера через запятую (R-1,R-4)? Зависимые тесты
   менять: да / нет?». Ответ -> команда:
   ```
   python3 .gigacode/skills/autotest-review/scripts/review.py approve <файл> <all | none | R-1,R-4> [--target-only]
   ```
   `--target-only` - когда на второй вопрос ответ «нет». Строки с «Кто» `human` скрипт не
   одобряет никогда - они уходят в итог. Ответ `none` -> итог, дальше не идёшь.
3. Компиляция до правок, копия исходников, правки скрипта (таймаут 900 секунд):
   ```
   python3 .gigacode/skills/autotest-review/scripts/review.py start <файл>
   ```
4. Задание на следующую правку:
   ```
   python3 .gigacode/skills/autotest-review/scripts/review.py next <файл>
   ```
   `ВСЕ ПРАВКИ СДЕЛАНЫ` -> шаг 6.
5. Одна правка: вывод после строки «ПРАВКА для агента pvatf-generator» передай агенту
   `pvatf-generator` дословно. Ответ агента - строка `Статус:`:

   | Статус | Команда |
   |--------|---------|
   | `ok` | `review.py mark <файл> <R-n> done` |
   | `failed` | `review.py mark <файл> <R-n> failed` |
   | `blocked` | вопросы документации по `references/autotest-rules.md`, правила 2-3 (метка - по технологии правки, ответ - в `.gigacode/data/doc-notes/<метка>.md`), потом снова шаг 4: `next` выдаст ту же правку с новым конспектом. Второй `blocked` на ту же правку -> `review.py mark <файл> <R-n> blocked` |

   Потом снова шаг 4.
6. Проверка (таймаут 900 секунд):
   ```
   python3 .gigacode/skills/autotest-review/scripts/review.py check <файл>
   ```
7. Код 1:
   - `ИТОГ: ошибок <n> · круг <k> из 3` -> `review.py next <файл>` выдаст задание `FIX`,
     передай его агенту `pvatf-generator` дословно (`mark` для `FIX` не нужен), потом снова шаг 6;
   - `ИТОГ: круг 3 из 3` -> откат:
     ```
     python3 .gigacode/skills/autotest-review/scripts/review.py rollback <файл>
     ```
8. Итог по шаблону - данные из `.gigacode/data/autotest-review/<класс>/REVIEW.md`.

## Контракт «вход -> выход»

Вход: путь к тест-классу.

Выход:
- изменённый тест-класс, классы шагов и констант, зависимые тесты (только одобренные);
- `.gigacode/data/autotest-review/<класс>/REVIEW-PLAN.md` - план и статусы (пишет скрипт);
- `.gigacode/data/autotest-review/<класс>/REVIEW.md` - отчёт (пишет скрипт);
- `.gigacode/data/autotest-review/<класс>/backup/` - копия исходников до правок.

Ответ в чате строго по шаблону:
```
Автотест: <файл> · review_status <checked | rolled-back>
Правки: сделано <n> · не сделано <n> (<R-n: причина>) · пропущено <n>
Компиляция: до <ok | skipped> · после <ok | failed | skipped>
Изменено: <файлы через запятую; нет - «нет»>
Осталось человеку: <строки раздела «Осталось человеку» отчёта; нет - «нет»>
Дальше: «Напишите: /orchestrator разметь тесты», если в «Осталось человеку» есть MARKUP; иначе «нет»
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| `find`: `НЕТ ФАЙЛА` или `НЕ ТЕСТ` | Скажи человеку вывод дословно, попроси путь к тест-классу. Дальше не идёшь |
| `find`: `ПРАВКИ ИДУТ` | Прошлая проверка не закончена: шаг 4 (продолжить) или, если человек просил начать заново, `rollback` и снова шаг 1 |
| `start`: `ПРОЕКТ НЕ КОМПИЛИРУЕТСЯ ДО ПРАВОК` | Ничего не правишь. Итог: «проект не компилируется и без правок», строки `КОМПИЛЯЦИЯ` из вывода, предложи `/orchestrator настрой окружение` |
| `start` или `check`: таймаут компиляции | Запусти ещё раз. Снова таймаут - `--no-compile`, в итоге «компиляция не проверена» |
| Агент ответил не по шаблону | Перезапусти агента 1 раз с тем же заданием. Снова - `mark <файл> <R-n> failed` |
| `pvatf-docs`: `MCP НЕДОСТУПЕН` | `mark <файл> <R-n> blocked`; в итоге - «документация недоступна» |
| Человек просит откатить | `review.py rollback <файл>`, итог по шаблону |

## Чек-лист проверки

- [ ] Находки взяты из вывода `find`; сам находок не добавлял.
- [ ] Правки начались только после ответа человека и команды `approve`.
- [ ] Каждая правка агента прошла через `next` -> агент -> `mark`; код сам не писал.
- [ ] Последний `check` - после всех правок, или выполнен `rollback`.
- [ ] Ответ в чате - по шаблону; коммит не сделан.
