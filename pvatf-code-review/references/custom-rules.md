# Кастомные правила команды / фрейма (заполняется вами)

Сюда команда вписывает свои правила код-ревью: соглашения проекта, требования вашего
тест-фреймворка, локальные best practices, запреты и предпочтения. Скилл читает этот файл и
учитывает правила отсюда наравне со встроенными.

Заполнять можно руками или скиллом `architecture-rules` - он анализирует архитектуру проекта
(иерархию модулей, слои, исключения) и дописывает правила сюда по шаблону `### CR-<n>`.

Как это работает:
- **Файл пустой** (ниже нет ни одного правила) -> скилл его игнорирует, ведёт себя как
  обычно. Не выдумывай правила за команду.
- **В файле есть правила** -> применяй их при ревью (Шаг 3) и, если правило проверяемо
  тестом, доказывай так же, как встроенные (Шаг 4). В отчёте помечай такие находки как
  источник «кастомное правило команды».
- Конфликт с встроенным правилом -> кастомное правило команды приоритетнее (это их проект).

Формат - свободный, но лучше по одному правилу на пункт и с пометкой, проверяемо ли тестом.
