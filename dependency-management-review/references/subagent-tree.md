# Разбор дерева зависимостей сабагентами (для мультимодуля)

Этот файл нужен только на шаге «Дерево зависимостей» (Шаг 5 SKILL.md) и только для
**мультимодульных** проектов. Идея: вывод `dependency:tree` по одному модулю бывает
огромным, и если читать его самому по всем модулям - контекст переполняется, и ты теряешь
важные детали. Поэтому на каждый модуль запускается отдельный сабагент с жёстким промптом;
он сам читает громоздкое дерево и возвращает тебе короткий структурированный результат по
фиксированному шаблону. Ты только собираешь эти результаты - большой вывод дерева к тебе не
попадает.

## Когда применять

- Для **любого мультимодульного** проекта (модулей 2+) это ОБЯЗАТЕЛЬНО, а не по желанию.
  Запусти по одному сабагенту на КАЖДЫЙ модуль. Это правило часто пытаются пропустить -
  не пропускай его.
- Единственная причина не запускать сабагентов - инструмент их запуска (Task/Agent)
  физически отсутствует в окружении. Только тогда пройди модули сам, последовательно, теми
  же командами из Шага 5, заполни тот же шаблон вручную и напиши в отчёте, что сабагенты
  были недоступны. Оправдания «долго», «модуль маленький», «и так понятно» не считаются.
- Для монолита сабагенты не нужны - один модуль разбираешь сам.

## Как запускать

1. Возьми список модулей из блока «Картина проекта» (карта модулей).
2. На **каждый** модуль запусти по одному сабагенту. Если инструмент позволяет - запускай
   их параллельно (в одном заходе), это быстрее; результаты собери по мере готовности.
3. Передай сабагенту промпт ниже дословно, подставив путь проекта, систему сборки и имя
   модуля. Ничего лишнего в промпт не добавляй - он специально узкий, чтобы слабый агент
   не отвлёкся.
4. Полученные шаблоны сложи в свой файл заметок в блок «Дерево: результаты по модулям».
   Затем преврати находки в строки правил (обычно G-C-07 / M-C-06 - выравнивание семейств,
   или конфликт версий) с пометкой «транзитивно, из dependency-дерева, модуль <имя>».

## Жёсткий промпт для сабагента (копируй дословно, подставь значения в <...>)

```
Ты анализируешь дерево зависимостей ОДНОГО модуля. Действуй строго по шагам и не делай
ничего сверх этого. Не меняй файлы. Верни ТОЛЬКО заполненный шаблон в конце - без
рассуждений, без пересказа всего дерева.

Проект: <абсолютный путь к корню проекта>
Система сборки: <Maven | Gradle>
Модуль: <имя модуля, напр. :web или web>

Шаг 1. Построй дерево зависимостей ровно этого модуля:
  - Maven:  mvn -q -pl <модуль> dependency:tree -Dverbose
  - Gradle: ./gradlew :<модуль>:dependencies --configuration runtimeClasspath
  Если команда падает (нет сборщика, нет сети, запуск запрещён) - не выдумывай дерево:
  в шаблоне поставь «Статус запуска: НЕ УДАЛОСЬ» и причину, остальные поля оставь пустыми.

Шаг 2. Найди в выводе три вещи:
  (а) КОНФЛИКТЫ ВЕРСИЙ - один и тот же group:artifact встречается в разных ветках дерева с
      разными версиями. В Maven на них указывают пометки «(version omitted for conflict
      with ...)» / «(version managed from ...)»; в Gradle - стрелка «X -> Y» (версия
      подменена при резолюции).
  (б) РАЗЪЕХАВШИЕСЯ СЕМЕЙСТВА - члены одного семейства (общий префикс группы: jackson-*,
      spring-*, org.junit*, selenium-*, allure-*, testcontainers-*) с разными версиями.
  (в) ПОДОЗРИТЕЛЬНЫЕ ПОДМЕНЫ - запрошена одна версия, а разрезолвилась заметно другая
      (особенно даунгрейд), что может ломать совместимость.

Шаг 3. Верни РОВНО такой шаблон (сохрани заголовки полей, коротко, дефис вместо тире):

### Модуль: <имя>
- Команда: <точная команда, которую ты выполнил>
- Статус запуска: OK | НЕ УДАЛОСЬ (<причина>)
- Конфликты версий:
  - <group:artifact>: <верс1> vs <верс2>, победила <верс>; ветки: <кто тянет каждую>
  - (если нет - напиши: нет)
- Разъехавшиеся семейства:
  - <семейство>: <член1 верс1>, <член2 верс2>
  - (если нет - напиши: нет)
- Подозрительные подмены версий:
  - <group:artifact>: запрошена <x>, разрезолвлена <y>
  - (если нет - напиши: нет)
- Итог: OK (находок нет) | ЕСТЬ НАХОДКИ (<число>)
```

## Что делать с результатами

- Каждую строку «Конфликты версий» / «Разъехавшиеся семейства» / «Подозрительные подмены»
  переведи в находку правила (G-C-07 или M-C-06, при явном конфликте версий - под правилом
  про расхождение) с уровнем по обычной логике и пометкой «транзитивно, из
  dependency-дерева, модуль <имя>».
- Если у какого-то модуля «Статус запуска: НЕ УДАЛОСЬ» - вынеси это в отчёт, раздел
  «Требует внимания человека», с точной командой, чтобы человек прогнал вручную.
- После сбора всех модулей всё равно сделай **полный** прогон по проекту
  (`mvn -q dependency:tree -Dverbose` / `./gradlew dependencies`) сам или отдельным
  сабагентом - он ловит конфликты, возникающие только при сборке всего реактора вместе.
