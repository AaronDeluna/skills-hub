# Общие правила окружения и генерации автотестов

Действуют в скиллах `env-check`, `env-update`, `autotest-plan`, `autotest-gen`, `autotest-review`. Прочитай этот
файл целиком в начале работы скилла. В SKILL.md - только то, что касается одного скилла; при
расхождении прав этот файл. Источник - `shared/autotest-rules.md` набора, копии в `references/`
обновляет `scripts/sync_shared.py`. Правь только источник. **Это автономная версия набора.**

1. **О фрейме знаешь только то, что есть в документации.** Источники по порядку: конспект
   `.gigacode/data/doc-notes/` -> документация MCP через агента `pvatf-docs` -> проект-пример
   через агента `pvatf-examples` (только если человек дал путь) -> код самого проекта
   (как там уже сделано) -> место не делается и записывается в отчёт. `get_pv_at_doc` сам не
   вызываешь. `get_pvat_release_notes` и `get_pvat_changelog` вызываешь сам (таймаут 120
   секунд; таймаут или ошибка -> повтори 1 раз, снова -> поступай как при ошибке инструмента
   по таблице ошибок скилла), ответ сразу сохраняешь в файл дословно. ЗАПРЕЩЕНО: открывать `.jar`, лазить в `~/.m2`, `.gradle`,
   кэши IDE, запускать `javap`, искать в интернете, писать «по памяти» и «по аналогии».
   Нельзя: «`KafkaService.producerClient()` - так обычно делают». Нужно: «`D-kafka-2`:
   `KafkaService.producerClient()`».
2. **Перед вопросом документации - конспект.**
   `python3 .gigacode/skills/<скилл>/scripts/notes.py find <tech> <2-4 слова>`. Запись со
   статусом `найден` отвечает на вопрос - вопрос не задаёшь. Новый ответ `pvatf-docs`
   дописываешь в `.gigacode/data/doc-notes/<tech>.md` записью `## D-<tech>-<n> · <вопрос>`, ID -
   `notes.py next <tech>`.
3. **Задание агенту `pvatf-docs` - только по этому шаблону, не больше 5 вопросов:**
   ```
   - Технология: <метка> · <обычное название>
   - Раздел документации: <название раздела или «нет в списке»>
   - Вопросы:
     1. <вопрос с именами: что сделать, каким классом фрейма>
   - Якорь технологии: <класс-якорь из таблицы ниже или «нет»>
   - Ключевые слова из прошлых ответов документации: <раздел «Ключевые слова документации» конспекта или «нет»>
   - Формулировки, которые уже пробовали и они НИЧЕГО не дали: <из конспекта или «нет»>
   - Уже есть в конспекте: <ID и вопросы или «нет»>
   ```
   Якорь - класс, который уже встречался в примерах генерации набора; не знаешь - «нет»
   (агент тогда начнёт с названия раздела).

   | Метка | Раздел документации | Якорь |
   |-------|---------------------|-------|
   | `env` | Быстрый старт | environment-junit5 |
   | `rest` | Работа с Rest API | RestService |
   | `websocket` | Работа с WebSocket | WebSocketService |
   | `grpc` / `graphql` | Работа с gRPC / Работа с GraphQL | нет |
   | `db` | Работа с Базами Данных | DatabaseService |
   | `opensearch` | Работа с OpenSearch/ElasticSearch | OpenSearchService |
   | `kafka` | Работа с Kafka | KafkaService |
   | `ui` | Работа с UI Playwright / Работа с UI Selenide | нет |
   | `mobile` | Работа с Appium Android / Работа с Appium iOS | AndroidPage |
   | `audit` / `journal` / `abyss` / `metrics` | Работа с Единым Аудитом / Журналами ЕФС и ППРБ / PVM-ABYSS / хранилищем метрик | AuditFlow / JournalFlow / нет / MetricsFlow |
   | `fixtures` / `testcontainers` / `sbermock` / `toggler` / `launcher` | Сервис для работы с Fixtures / Работа с TestContainers / Работа с SberMock / Работа с Toggler / Работа с Launcher | FixtureService / ContainerService / SberMockService / TogglerService / LauncherService |
   | `timeouts` / `openshift` / `dataconverter` | Сервис для работы с Таймаутами / Работа с OpenShift и Kubernetes / Работа с DataConverter | нет / нет / DataConverterService |
   | `value` / `session` / `invocation` | ValueService / Работа с Сессиями / Работа с Invocation | ValueService / нет / нет |
4. **Память - это файлы, а не чат.** Состояние окружения - `.gigacode/data/autotest/ENV*.md`,
   `ENV.json`; генерации - `.gigacode/data/autotest/<ID ТК>/`. Результат этапа сразу пиши в
   файл, потом следующий этап. Сомневаешься, где ты, - файл главнее памяти.
5. **Делаешь только своё.** Меняешь только файлы, которые называет этап. Увидел другое, что
   надо поправить, - строка в отчёт («Осталось человеку»), не правка.
6. **Код по правилам набора.** Слои: тест -> шаги предметной области -> базовый слой
   технологии -> фрейм. Проверки - matchers фрейма в `.should(...)`, без JUnit `assert*`,
   AssertJ, `Thread.sleep`, `var`, своих matchers, DTO ответа и вспомогательных методов в
   тест-классе. Значения подключения (адреса, логины, токены) в коде не пишутся - только
   ключи настроек. Самопроверка кода - скрипт этапа, а не «посмотрел - вроде нормально».
7. **Сабагентов запускает работающий скилл** по готовым заданиям из своих `references/`.
   Ответ не по шаблону агента не используется: перезапусти агента 1 раз, снова не по
   шаблону - место не делается, причина в отчёт. Агенты набора лежат в `.gigacode/agents/`
   (ставит `next_action.py`); запуск - по имени. Режим `fork` не используешь. Агента с таким
   именем инструмент не знает -> обычный сабагент, первая строка задания: «Прочитай файл
   .gigacode/agents/<имя>.md - текст после второй строки --- это твоя инструкция, выполняй
   её.», дальше то же задание.
8. **Вопросов человеку нет** - это автономная версия набора, отвечать некому. Где скилл
   пишет «спроси человека» - не спрашивай и не жди: остановись, запиши причину в файл
   процесса (раздел «Решения и блокеры» плана или «Осталось человеку» отчёта) и закончи
   итогом со строкой `Нужно от человека: <что именно>`. Значения по догадке не подставляй.
9. **Каждый внешний вызов - с таймаутом.** Сборка - 900 секунд (после обновления фрейма -
   1800), MCP - ответ не пришёл за 120 секунд: повтори 1 раз, потом ошибка по таблице скилла.
10. **Git.** Коммиты, `push`, PR - только по прямой просьбе человека. В конце работы покажи,
    какие файлы изменены (`git status --short`).
11. **Язык.** Пиши на русском, короткий дефис `-`. ID (`TC-...`, `G-3`, `D-rest-2`) и статусы
    (`planned`, `done`, `ok`, `stub`) - латиницей. С человеком - на «вы», коротко.
