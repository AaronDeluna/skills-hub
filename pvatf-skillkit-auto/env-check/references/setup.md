# Настройка окружения (режим setup)

Часть скилла `env-check`. Открывай, только когда SKILL.md направил сюда.

Правило одно: что и как подключать - только из документации фрейма (агент `pvatf-docs`) или
из проекта-примера (агент `pvatf-examples`, если человек дал путь к драфту). Имена
зависимостей, классов, ключей по памяти не пишешь. Нельзя: «добавлю ru.sber.qa:allure2:3.4.1,
так обычно». Нужно: «D-env-2: зависимость `<group:artifact>` из ответа pvatf-docs, версия -
`${<свойство версии фрейма из ENV.json>}`».

## 1. Собери вопросы

Одна строка `ПРОБЛЕМА` -> один вопрос. Вопросы - по таблице, дословно:

| Код проблемы | Вопрос для pvatf-docs |
|--------------|-----------------------|
| `MANDATORY_DEPENDENCIES_MISSING` (`<артефакты>`) | Как подключить зависимости `<артефакты>` фрейма в `<Maven / Gradle>`: groupId, artifactId, версия |
| `RECOMMENDED_DEPENDENCIES_MISSING` | Какие зависимости нужны для логирования и отчёта Allure в проекте на фрейме: slf4j-api, slf4j-simple, allure-junit5, aspectjweaver |
| `ENVIRONMENT_CONFIGURATION_MISSING` | Как объявить класс конфигурации окружения (EnvironmentConfiguration) и подключить его к тестам |
| `STASH_CONFIGURATION_MISSING` | Как объявить AllureDataSourceServiceConfiguration для передачи данных между шагами (Stash) |
| `PERFECCIONISTA_PROPERTIES_MISSING` / `PERFECCIONISTA_REQUIRED_KEY_MISSING` | Какие ключи нужны в perfeccionista.properties, в том числе perfeccionista.attachment.dir |
| `MAVEN_PLUGINS_MISSING` (`<плагины>`) | Как настроить плагины `<плагины>` для запуска тестов фрейма и отчёта Allure |
| `TEST_ROOT_MISSING` | Какая структура каталогов нужна проекту автотестов на фрейме |

Проблемы с кодами `COMPILE_*` здесь не исправляются: компиляцию чинит человек или
`env-update` (если ошибки после обновления версии).

## 2. Спроси документацию

Сначала конспект (общий для окружения и генерации, `.gigacode/data/doc-notes/`):
```
python3 .gigacode/skills/env-check/scripts/notes.py find env <2-4 слова вопроса>
```
Запись со статусом `найден` отвечает на вопрос -> бери её, вопрос не задавай.

Остальные вопросы (не больше 5 за один вызов) - агенту `pvatf-docs` по шаблону
`references/autotest-rules.md`, правило 3, технология `env`.

Каждый блок ответа допиши в `.gigacode/data/doc-notes/env.md` записью `## D-env-<n> · <вопрос>`
(поля - как в ответе агента, файла нет - создай). ID - следующий свободный, его печатает
`python3 .gigacode/skills/env-check/scripts/notes.py next env`. Словарь «Ключевые слова
документации» из ответа замени в конце файла целиком.

## 3. Правки

По одной правке на проблему, только в файлах сборки и конфигурации:
- зависимость - в тот же `pom.xml` / `build.gradle(.kts)`, где уже стоят зависимости фрейма;
  версия - ссылка на свойство версии фрейма (строка `ВЕРСИЯ` из сводки), не число;
- класс конфигурации - в базовый пакет тестов из строки `ПРОЕКТ`, подпакет `config`;
- `perfeccionista.properties` - в `src/test/resources/` модуля с тестами.

Ответ документации «НЕТ В ДОКЕ» или «найден частично» без нужного имени -> правку не делай.

## 4. Отчёт ENV-SETUP.md

Файл `.gigacode/data/autotest/ENV-SETUP.md`, шаблон дословно (новый запуск дописывает блок в конец):

```markdown
## Настройка <дата время>

|----------|------|-------------|-----------|

Проверка после правок: <СТАТУС из env_check.py>, проблем было <n>, стало <m>
```
