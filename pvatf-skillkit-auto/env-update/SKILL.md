# Обновление фрейма PVATF

Скилл запускает `orchestrator`. Работа идёт по этапам 1-9, состояние - в
`.gigacode/data/autotest/ENV-UPDATE.md`: оборвался чат - следующий продолжает с этапа из шапки.
Сначала прочитай `references/autotest-rules.md`, потом `references/update.md` - там этапы.

## Когда использовать / когда не использовать

| Просьба | Что делаешь |
|---------|-------------|
| «обнови окружение», «обнови фрейм до последней версии», «продолжи обновление» | этот скилл, все этапы |
| «обнови фрейм до 3.5.0» (версия названа) | этот скилл, на этапе 4 версия - названная, а не из release notes |
| «откати обновление» | этап 9, ветка «откат» |
| проект не компилируется ещё до обновления | не этот скилл: `env-check`, режим setup, или человек |

## Предусловия

- Запуск из корня проекта; рабочее дерево git без незакоммиченных правок
  (`git status --porcelain -- . ':!.gigacode'` пусто). Откат возвращает файлы командой
  `git checkout`, поэтому чужие незакоммиченные правки он бы стёр.
- Python 3.8+ (команды `python3 ...`; на Windows, где нет `python3`, - `python ...` или `py -3 ...`).
- MCP-инструменты `get_pvat_release_notes` и `get_pvat_changelog` (сервер автогенерации
  автотестов) - вызываешь сам; `get_pv_at_doc` - только через агента `pvatf-docs`.
- Скрипт проверки окружения из скилла `env-check` (этапы 1, 7, 8).

**Скрипты лежат в `.gigacode/skills/env-update/scripts/` и `.gigacode/skills/env-check/scripts/`.**
Скрипта по этому пути нет -> найди один раз:
`find . ~/.gigacode -path "*env-*/scripts/env_*.py" 2>/dev/null | head -2` - и подставляй найденное.

## Шаги

1. Прочитай шапку `.gigacode/data/autotest/ENV-UPDATE.md`. Файла нет -> создай по шаблону
   `references/report-template.md`, `update_stage: 1`. Есть и `update_status: in-progress` ->
   продолжай с этапа `update_stage`. Просят откатить, статус `done` или `failed` -> сразу этап 9,
   ветка «откат», `reset` не запускай. Иначе статус другой (`done`, `failed`, `rolled-back`) ->
   переименуй файл в `ENV-UPDATE-<from>-<to>.md`, запусти
   `python3 .gigacode/skills/env-update/scripts/env_update.py reset` (стирает копии файлов
   сборки прошлого обновления, ждёт `СБРОШЕНО`) и создай новый файл по шаблону, `update_stage: 1`.
2. Выполняй этапы `references/update.md` по порядку, от текущего до 9. После каждого этапа
   обнови в шапке `update_stage` и допиши строку в раздел «Журнал».
3. Этап закончился ошибкой из таблицы «Обработка ошибок» -> поступай по таблице, дальше не иди.
4. После этапа 9 покажи итог по шаблону из раздела «Контракт».

## Контракт «вход -> выход»

Вход: просьба человека; необязательно - целевая версия.

Выход:
- изменённые файлы сборки (версия фрейма) и исправленный код - в рабочем дереве, без коммита;
- `.gigacode/data/autotest/ENV-UPDATE.md` по шаблону, `update_status: done | failed | rolled-back`;
- `.gigacode/data/autotest/env-update/` - release notes, changelog, список имён, копии файлов сборки;
- ответ в чате строго по шаблону:

```
Обновление фрейма: <было> -> <стало> · <done | failed | rolled-back>
Файлы сборки: <файл:строка - свойство> (по строке)
Изменения из changelog, затронувшие проект: <имя - мест n - что сделано>; нет - «нет»
Компиляция после обновления: <ok | failed: первые 3 ошибки>
Исправлено в коде: <файл - что заменено - основание D-<tech>-<n> / changelog>; нет - «ничего»
Проверка окружения: <СТАТУС из env_check.py>
Дальше: <«проверьте изменения: git diff» или что осталось на человеке>
```

## Обработка ошибок

| Что случилось | Что делаешь |
|---------------|-------------|
| Скрипт скилла без компиляции и без MCP-вызова не закончил работу за 120 секунд | Прерви вызов, покажи вывод дословно, дальше не иди. Повторно не запускай |
| Этап 1: компиляция failed до обновления | `update_status: failed`, причина «проект не компилировался до обновления». Предложи `/orchestrator настрой окружение`. Версию не трогай |
| MCP-инструмент не найден или ошибка | Повтори вызов 1 раз. Снова ошибка -> `update_status: failed`, причина - текст ошибки дословно, версию не трогай |
| Release notes без номеров версий (`ВЕРСИЙ НЕТ`) | `update_status: failed`, причина «в release notes нет номеров версий»; итог со строкой `Нужно от человека: целевая версия фрейма` |
| Новая версия не новее текущей | `update_status: done`, «уже последняя версия <n>» |
| Компиляция не прошла после 3 кругов исправлений (этап 8) | Этап 9, ветка «откат» |
| Этап 7: `COMPILE_TIMEOUT` (компиляция дольше 1800 секунд) | Повтори этап 7 1 раз; снова `COMPILE_TIMEOUT` - откат |
| В changelog и документации нет замены удалённому имени | Это место не правь. Запиши в «Осталось человеку» файл, строку и имя |

## Чек-лист проверки

- [ ] Версия взята из ответа `get_pvat_release_notes` скриптом `env_update.py latest`, не по памяти.
- [ ] `env_update.py bump` вывел `ИЗМЕНЕНО` по каждому объявлению текущей версии.
- [ ] Каждое изменение кода опирается на changelog или запись `D-<tech>-<n>` конспекта.
- [ ] Последний запуск `env_check.py` - после всех правок; компиляция `ok`.
- [ ] Шапка `ENV-UPDATE.md`: `update_status` не `in-progress`; ответ в чате - по шаблону.
- [ ] Коммит не сделан: изменения показаны человеку.
