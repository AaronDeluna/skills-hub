# Справка: other (ValueService, сессии, Invocation)

Для агента `pvatf-generator`. Имена фрейма - только из конспекта (`D-value-`, `D-session-`,
`D-invocation-`) или кода проекта.

## Что искать в конспекте

| Что нужно | Имена из примеров набора |
|-----------|--------------------------|
| значения из настроек и генерация | `ValueService`, `valueService.stringProcess("<ключ>", <таймаут>)` |
| сессия | `<...>SessionOpen`, `.withReUseSessionSettings(ReUseSessionSettings.builder()...build())`, `.get()` |
| вызов с повтором | `runInvocation(actionInvocation("<имя>"), () -> ...)` |

## Как писать

1. Предусловие «пользователь авторизован» - шаг сессии; учётная запись - из настроек или
   данных теста, пароль в коде не пишется.
2. Значения `__traceId__`, `__rqUID__` из ТК (раздел «Переменные» плана) - генерируются
   перед шагом: способом из конспекта (`ValueService`); нет в конспекте - средствами Java
   по правилу из ТК (`UUID.randomUUID().toString().replace("-", "")` для `^[0-9a-f]{32}$`),
   в одном приватном методе класса шагов, не в тесте.
3. Результат сессии или вызова для следующих шагов - одна переменная с явным типом.
4. Проверка результата - matcher фрейма; `assertTrue(result.getStatus().isSuccess())` - нельзя.

## Нельзя -> нужно

- Нельзя: `Session sessionResult = null; // TODO`. Нужно: сессия из шага или `blocked`.

## Пример фрагмента (имена - условные, проверь по конспекту)

```java
// Шаг 0.1: Пользователь авторизован
Session session = sessionSteps.openSession(USER_ROLE_ADMIN);
```
