# Оркестратор миграции на PVATF

Миграция разбита на юниты, всё состояние лежит в файлах `.gigacode/data/migration/`. Ты не
мигрируешь код и не строишь карту. Твоя работа: понять, чего хочет человек, узнать у
скрипта следующее действие, запустить ОДИН скилл и коротко отчитаться.

**Автономная версия.** Запрос приходит от терминального приложения, человека рядом нет.
Вопросов не задавай и ответа не жди: где нужна развилка - решение по правилам скиллов
(`references/core-rules.md`, правило 8). Исключение одно - вопросы разметки на Этапе 2
карты: их выводит `migration-map` блоком `<<<PVATF-QUESTIONS`, ответы приносит приложение.

Сначала прочитай `references/core-rules.md` - общие правила миграции.

**Скрипты этого скилла лежат в `.gigacode/skills/orchestrator/scripts/`.** Команды ниже - готовые:
копируй и запускай как есть, из корня мигрируемого проекта (там, где `.gigacode/`); нужна
Java 11+. Скрипта по этому пути нет (скиллы установлены в другое место) -> найди его один
раз: `find . ~/.gigacode -path "*orchestrator/scripts/*.java" 2>/dev/null | head -3` - и подставляй
найденный каталог. Скрипт упал с ошибкой -> покажи ошибку в чате и сделай то же самое
командами вручную по описанию в этом скилле; молча пропускать скрипт нельзя.

## Шаг 1 - Чего хочет человек

Первая подходящая строка сверху:

| Просьба | Что делаешь |
|---------|-------------|
| в сообщении ответы на вопросы разметки: JSON `{"answers": {"Q-<n>": ...}}` или строки `Q-<n>: <значение>` | Запусти `migration-map`, передай ответы дословно (Этап 2, шаг 1б, п.6). Скрипт в этом чате не нужен |
| показать статус, «что сделано» | `references/status.md`. Скиллы не запускай |
| сжать карту, «карта разрослась» | `references/compress.md`. Скиллы не запускай |
| перенести тесты из другого (старого) проекта в этот | Скажи: «Перенос из старого проекта в новый пока не поддерживается. Эти скиллы мигрируют проект на месте: целиком или только ядро». Больше ничего не делай |
| проверить миграцию («как прошла миграция») | Запусти `migration-review`. Карта не обязательна. Названные старые библиотеки передай дословно |
| только ядро / полная миграция («тесты не трогай», «теперь переводи тесты») | `references/scope.md`, потом Шаг 2 |
| проект сильно изменился, карта устарела | Запусти `migration-map`: режим обновления (Этап 6) |
| кто делает подшаги: «подшаги делай сабагентами», «режим менеджера» / «подшаги делай сам», «без сабагентов» | Карты нет -> передай просьбу в `migration-map`. Карта есть -> в разделе 1 карты замени строку на `- Режим исполнения: менеджер · основание: попросил человек` (или `сам`), скажи человеку, что режим переключён. Потом Шаг 2, если просил ещё что-то |
| всё остальное («мигрируй», «продолжи», «сделай M-012», «с M-001 по M-003») | Шаг 2 |

Выпиши из просьбы и передай дальше дословно: названные технологии и пути к проекту-примеру
или исходникам фрейма (их получает `migration-map`); названный юнит, диапазон или список
(их получает скрипт в Шаге 2).

## Шаг 2 - Спроси скрипт, что делать

```
java -Dfile.encoding=UTF-8 .gigacode/skills/orchestrator/scripts/NextAction.java [M-012 | M-001..M-003 | M-001,M-004]
```

Аргумент - только если человек назвал юнит, диапазон или список. Скрипт читает карту и
печатает `ДЕЙСТВИЕ:` и `ПОЧЕМУ:`. Ещё он ставит агентов кита (`pvatf-*`) в `.gigacode/agents/`
проекта, если их там нет или они устарели. **Шаг обязателен в каждом чате:** без вывода скрипта
скиллы не запускаешь; обе строки вывода покажи человеку дословно. Делай ровно то, что
скрипт сказал, сам юнит не выбирай:

| ДЕЙСТВИЕ | Что делаешь |
|----------|-------------|
| `агенты установлены` | Скрипт записал агентов кита в `.gigacode/agents/`. Покажи обе строки вывода и скажи: «Агенты миграции установлены или обновлены. Перезапустите GigaCode (выйдите и запустите заново) и повторите запрос». Скиллы не запускай |
| `migration-map` | Запусти `migration-map`, передай технологии и пути, если были |
| `вопросы разметки` | Запусти `migration-map`: он выведет блок вопросов разметки (Этап 2, шаг 1б) и остановится. Сам вопросов не задавай и значений не подставляй |
| `одобрение карты` | Человека не спрашивай: запусти `migration-map` - он доделает самопроверку Этапа 6 и сам поставит `map_status: approved` |
| `вопросы` | `references/questions.md`: доведи записи раздела 6 до решения сам. Человека не спрашивай |
| `карта повреждена` | Покажи человеку причину из `ПОЧЕМУ` дословно. Скиллы не запускай: по повреждённой таблице юнитов нельзя понять, что сделано |
| `migration-step M-<nnn>` | Запусти `migration-step` на этот юнит |
| `migration-step пачка: ...` | Запусти `migration-step` ОДИН раз, передай «пачка: <ID через запятую>» |
| `нельзя`, `нечего делать` | Объясни человеку причину из `ПОЧЕМУ`, скиллы не запускай |
| `заблокировано` | Покажи блокеры: раздел «Блокер» карточек `blocked` и строки `решить человеку` (`grep -n "решить человеку" .gigacode/data/migration/MIGRATION-MAP.md`) |
| `ядро готово` | Скажи: ядро переведено, тесты не тронуты; продолжить - по просьбе о полной миграции |
| `migration-review` | Запусти `migration-review` |
| `проверка не сходится` | Покажи сводку последнего круга из `MIGRATION-REVIEW.md` и повторяющиеся находки - их посмотрит человек. Новый круг не запускай |
| `финал` | `references/final.md` |

Строка `ЗАМЕТКА:` -> добавь её смысл в итоговый ответ. Скрипт упал или карта не читается ->
скажи человеку, что именно вывел скрипт; сам таблицу юнитов не разбирай.

## Шаг 3 - Запусти один скилл и дождись его конца

Вызови выбранный скилл через механизм вызова скиллов. С этого момента работаешь по SKILL.md
этого скилла: его правила главнее этого файла. Когда скилл закончил - второй скилл в этом
чате не запускай.

## Итоговый ответ человеку

Коротко:
- что было на входе и какой скилл запущен;
- что он сделал (этап карты / юнит и его статус);
- прогресс: `done` X из N юнитов;
- что осталось на человеке (строки `решить человеку`, решения из раздела 6 карты; пуш не делается);
- что дальше: **«Откройте новый чат и напишите: `/orchestrator Продолжи миграцию`»**.
