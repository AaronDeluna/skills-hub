# Что ищет скрипт и как читать план

Часть скилла `autotest-review`. Открывай, когда нужно объяснить человеку строку плана или
понять, почему правка попала (не попала) в план. Ищет только скрипт `review.py find`;
вручную находки не добавляешь.

## Типы правок

| Тип | Что нашёл скрипт | Кто делает |
|-----|------------------|------------|
| `MR-<n>` | нарушение правила кода (проверки те же, что в `autotest-gen check`) | агент; `MR-21` (TODO), `MR-49` и `STUB` - человек |
| `SQL` | значение склеивается в текст SQL (`"... WHERE id = '" + id`) | агент |
| `MR-22` | пустой `catch (...) {}` | агент |
| `DISABLED` | `@Disabled` / `@Ignore` без причины | человек (правило `MR-10`: тесты не отключаем и не включаем без решения) |
| `STATIC-STATE` | `static` поле без `final` - состояние переходит между тестами | человек |
| `MARKUP` | у метода `@Test` нет `@TmsLink` или `@DisplayName` | человек: разметка тестов |
| `CONST` | литерал для константы тест-класса | скрипт, если имя есть; иначе агент |
| `SHARED-CONST` | тот же литерал ещё в 2 и более тестах | агент, с зависимыми тестами |
| `DUP` | блок из 5 и более строк повторяется в тест-классе или в других тестах | агент |

## Какой литерал становится константой

Литералы берутся только из тела класса. Не берутся: комментарии, аннотации (`@TmsLink("...")`
остаётся как есть), строки `static final`, имена шагов `.step("...")`, `package`, `import`,
строки с находкой правила (их перепишет правка правила). Из оставшихся в план попадает:
- любое число, кроме `0` и `1`;
- строка длиннее 1 символа, в которой есть цифра (`"79991234567"`, `"PAY-001"`);
- любая строка, которая встречается в файле 2 и более раз;
- строка, которая есть ещё в 2 и более тестах проекта -> `SHARED-CONST`.

Нельзя: выносить `"Проверить статус"` из `.step(...)`. Нужно: только данные теста.

## Имя константы

По порядку, первое подходящее:
1. Литерал присвоен переменной: `String phone = "7999..."` -> `PHONE`.
2. Строка из латиницы, цифр и `._/-` до 40 символов: `"payments-api"` -> `PAYMENTS_API`.
3. Литерал - аргумент вызова: `withAmount(1500)` -> `AMOUNT` (приставки `with`, `set`, `get`,
   `by`, `for`, `send`, `add`, `put`, `select`, `check`, `should` убираются).
4. Имя уже есть в файле или не получилось -> в плане `<ИМЯ>`, правку делает агент.

## Статусы

`review_status` в шапке плана: `found` (план готов) -> `approved` (выбор сделан) -> `fixing`
(копия снята, правки идут) -> `checked` (компиляция после правок ok, новых нарушений нет) или
`rolled-back` (всё возвращено к копии).

Статус правки (последняя колонка): `todo` -> `approved` или `skipped` -> `done`, `failed`
(агент не смог) или `blocked` (нет в документации).
